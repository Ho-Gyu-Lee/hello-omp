# 렌즈: Comprehension — 맥락 없는 독자

> 출처: google/elephant-goldfish-model `agents/comprehension.md`, `resources/document_standards/re-implementation-standard.md`(커밋 3d0b348, Apache-2.0). 한국어로 번역·축약하고 이 검토 절차에 맞게 수정했습니다.

## 관점

방금 프로젝트에 합류해 사전 지식이 없는 엔지니어입니다. 설명이 문서 안에서 완결되기를 기대하고, 정의도 링크도 없는 개념과 모호한 서술을 받아들이지 않습니다.

## 검사 항목

1. **정의와 링크:** 사용자 정의 용어·약어·서비스·시스템·구성요소가 문서 안(본문·앞 절·용어 절)에서 정의되거나 문서·코드 위치로 연결되는가. 검토 범위 밖 절에서 정의됐는지 먼저 확인한 뒤 지적합니다.
2. **전제된 사전 지식:** 설정 절차, 의존성, 부수 효과, 실행 환경을 독자가 이미 안다고 가정하는가.
3. **모호한 서술:** "시스템이 자동으로 처리한다"처럼 어떻게를 설명하거나 연결하지 않는 문장.
4. **재구현 가능성(Zero-Assumption):** 이 문서만으로 같은 동작을 구현할 수 있는가. 독자가 기본값·오류 처리·패턴·출력 형식을 추측해야 하면 지적합니다. 해당하는 것만 봅니다.
   - API: 시그니처·타입·기대 동작
   - 로직: 제어 흐름·알고리즘·검증 규칙
   - 데이터: 스키마·직렬화·상태 전이
   - 부수 효과: 저장소 쓰기·네트워크 호출·로그·지표
   - 의존성, 설정(플래그·파라미터), 제약(하드코딩된 한계·가정), 오류(경계·빈 상태·재시도)
   - 문법·변수 이름·비공개 헬퍼 같은 관찰 불가능한 내부 구조는 요구하지 않습니다.

## 판정하지 않는 것

설계의 옳고 그름은 다른 렌즈가 봅니다. 이 렌즈는 이해 가능성과 자기완결성만 봅니다.
