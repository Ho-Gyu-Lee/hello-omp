# 코딩 스타일

이름·배치·빈 줄 등 표기 선택은 [언어 공통 코딩 스타일](/language-style.md)(모든 언어)과 [C/C++ 전용 규칙](/language-style-c-cpp.md)이 정본이다.

## 간결성 (Over-Engineering 금지)
- 요청하지 않은 파일·추상화·기능을 추가하지 않고 요청 범위만 가장 직접적으로 수정한다. YAGNI는 기능 범위에만 적용하며 버그 수정은 결함 클래스까지 고친다([버그 수정 원칙](/bugfix.md)).
- 요청 범위 밖의 동작·설계 제약을 보존한다. 근거 없이 로직을 만들어 넣거나 지우지 않고, 가독성·현대화·최적화를 이유로 무관한 리팩터링을 끼워 넣지 않는다. 필요한 변경이 확인된 계약과 충돌하면 영향·근거를 설명하고 사용자 결정을 받은 뒤 경계를 바꾼다. 요청된 버그 수정·계약 변경은 막지 않는다.
- 보존할 계약은 반환값만이 아니다. 호출 규약·ABI·데이터 레이아웃·소유권·수명·동시성·부수 효과와 성능 비용(할당·복사·간접 접근·조회)도 영향 범위에서 확인하며, 요구와 근거 없이 비용을 늘리지 않는다.

## 결정 사다리 (코드 생성 전, 위에서부터 첫 적용 단계에서 멈춤)
1. 존재할 필요가 있는가? 없으면 안 만든다.
2. 기존 코드에 같은 계약을 만족하는 구현이 있는가? 재사용한다.
3. 표준 라이브러리 → 네이티브 플랫폼 기능 → 이미 설치된 의존성 순으로, 되는 첫 번째를 쓴다.
4. 간단한 식·기존 호출로 끝나는가? 불필요한 분기·추상화를 추가하지 않는다. 여러 문장이나 블록을 한 줄로 압축하라는 뜻은 아니다.
5. 그제서야 동작하는 최소한만 쓴다.

사다리는 새로 작성하는 코드의 구현 선택 순서다. 기존 구현을 바꾸라는 지시가 아니며 교체는 위 보존 원칙과 요청 범위를 따른다.

## 근본 원리 (사건별 실수를 일반화)
- **계약 보존:** 표현식 정리·표준 기능 치환·멤버 재배치도 같은 결과만이 아니라 평가·수명·상태·비용 계약을 보존한다. 예: 필드 생략과 `undefined` 대입은 다른 상태이고, 표준·생성 기능은 중복 키·순서·복사 깊이·동등성 의미를 따로 확인해야 한다.
- **검증한 최종 값만 전파:** 외부 입력은 필드별 검증과 필드 조합·기존 상태 간 불변조건 검증을 마친 최종 값만 저장하고, 캐시·집계·이벤트·응답에도 그 값을 쓴다. 거부된 값이나 정규화 전 원본으로 상태·파생 결과를 오염시키지 않는다.
- **좌표계와 진행:** 변환 전후의 좌표계를 섞지 않고 반복 변환은 매번 진행을 보장한다. 예: 소문자 사본의 바이트 위치를 원문에 적용하지 않고(`strings.ToLower`는 `İ` U+0130 등에서 길이를 바꾼다), 치환 뒤 커서를 치환 범위 뒤로 옮겨 치환 문자열이 찾는 문자열을 포함해도 끝나게 한다.
- **존재·유일성은 원자적 저장 연산으로:** 최종 일관성 조회(예: DynamoDB GSI)가 아니라 기본키 대상 조건부 쓰기로 판정하고 충돌은 갱신 재시도로 처리하며, 유일하지 않은 키로 덮어쓰지 않는다.
- **부재·실패·실제 값을 구별:** 누락을 0으로 간주하거나 집계·세부 값을 중복 합산하지 않는다. 응답 의미 변경(예: 실패를 성공 응답에서 오류로)은 배포된 모든 호출자의 분기·재시도·집계를 바꾸므로, 구분은 구버전이 무시하는 추가 응답 필드나 신버전만 보내는 요청 옵션으로 더한다.

## 공개 API와 확장성
- 소비자가 안정적으로 선택·조합해야 하는 정책과 계약만 공개하고 내부 알고리즘 단계·임시 데이터 구조·구현 전용 튜닝은 숨긴다.
- 소비자별로 합법적으로 달라지고 의미·안전 범위·버전 호환 계약을 테스트할 수 있을 때만 설정을 공개한다.
- 구체적인 확장 요구 없이 `virtual`·`protected`·공개 setter·subclass hook을 선제적으로 추가하지 않는다. 설정이나 합성으로 충분한 문제에 상속 확장점을 만들지 않는다.

## 아키텍처 (설계/리팩토링 요청 시)
- 설계 방향은 [개발 방향](/direction.md)의 「설계」를 따른다. 삭제 시험: 지웠을 때 복잡도가 여러 호출자로 퍼지면 가치 있는 모듈이다.

## 서버 특화
- 메모리·네트워크 운영 항목은 [공통 서버 체크리스트](/development/server-checklist.md)를 따른다. 소유권·수명은 각 언어 런타임의 모델을 따르며 C/C++ 규칙을 다른 언어로 옮기지 않는다.
- 동시성·서버 구조 방향은 [개발 방향](/direction.md)을 따른다.
- 서버 코드 타입의 역할 접미사 어휘: `XxxPacket`, `XxxHandler`, `XxxManager`, `XxxSession`. 의무가 아니며 [적용 우선순위](/language-style.md#1-우선순위와-언어-수준)로 적용 여부를 정하고 기존 이름은 접미사 때문에 바꾸지 않는다.
