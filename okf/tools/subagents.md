# 서브에이전트 위임

## 직접 vs 위임
- 단순 파일/심볼 검색 → grep/glob/lsp 직접 사용(서브에이전트 불필요).
- 3회 이상 탐색이 필요한 넓은 조사 → 읽기 전용 탐색 전담 서브에이전트(`scout`)에 위임.
- 독립적 조사 여러 건 → 서브에이전트 병렬 실행으로 메인 컨텍스트 보호.

## 병렬·격리
- 병렬 fan-out 전에 공유 인터페이스·데이터 형식·의존성·완료 기준과 각 작업의 정확한 write-set 소유권을 고정한다.
- 의존성이 없고 write-set이 겹치지 않는 작업만 같은 배치에서 병렬 실행한다. 공용 파일이나 통합 경계가 겹치면 한 소유자에게 합치거나 선행 계약을 확정한 뒤 순차화한다.
- 코드 변경이 포함된 병렬 작업은 task 요청에 `isolated`를 명시해 격리한다. 실제 백엔드는 `isolation.backend`가 선택하며, 외부 캐시·서비스는 격리하지 않으므로 충돌 가능 리소스는 별도로 분리한다.
- 서브에이전트의 완료 보고는 산출물 수락이 아니다. 부모가 변경 파일과 계약 경계를 직접 다시 검증한 뒤 통합하며, `reviewer`·advisor의 판단은 실행 증거를 대체하지 않는다.
- 대규모 작업은 계획 수립 후 배치 실행하고 체크포인트에서 검증하며, 실패한 계약에 의존하는 작업은 진행하지 않는다.

## 에이전트 선택
- 역할별 에이전트와 사용 시점은 [에이전트 가이드](/agents/guide.md) 참조.
- 위임받은 에이전트도 작업 전 관련 OKF 개념을 확인하고 omp 기본 도구·스킬을 우선 사용한다.
