# 서브에이전트 위임

## 직접 vs 위임
- 단순 파일·심볼 조회와 이미 범위가 명확한 작업은 직접 처리한다. 먼저 직접 읽기·검색으로 경계를 잡고 호출 횟수만으로 위임하지 않는다.
- 넓고 미확인인 읽기 전용 저장소 조사가 남으면 현재 가용한 `scout`을 사용한다. 이미 연 파일의 사소한 정리나 단일 질문을 불필요하게 위임하지 않는다.
- `scout`에 명령 실행이 필요한 확인(`git diff --no-index`·`git log`·`--version`·빌드)을 맡기지 않는다. 관찰한 세션(2026-10-06)의 `scout`은 읽기·검색 도구만 가져 해당 요청을 미실행으로 반환했다. 가용 도구는 세션마다 확인하고, 실행 근거가 필요하면 통합 담당자가 직접 실행하거나 실행 도구가 있는 에이전트에 맡긴다.
- 독립적으로 수행할 수 있는 실질적인 작업들이 있거나 읽을 자료가 메인 컨텍스트를 과도하게 차지할 때 분리한다. 병렬 위임은 같은 배치에 묶고, 공유 선행 조건은 통합 담당자가 해결한다. 독립 검토의 필수 시점은 [워크플로](/workflow.md)를 따른다.

## 병렬·격리
- 병렬 fan-out 전에 공유 인터페이스·데이터 형식·의존성·완료 기준과 각 작업의 정확한 write-set 소유권을 고정한다.
- 작업용 파일은 부모가 [워크플로](/workflow.md)의 정확한 작업 루트·작업-ID·파일 소유권을 전달하고 같은 디렉터리에 모은다. 격리 환경의 대응 경로·증거 수집과 TypeScript+Bun 실행 기준도 위임 계약에 포함한다.
- 의존성이 없고 write-set이 겹치지 않는 작업만 같은 배치에서 병렬 실행한다. 공용 파일이나 통합 경계가 겹치면 한 소유자에게 합치거나 선행 계약을 확정한 뒤 순차화한다.
- 코드 변경이 포함된 병렬 작업은 task 요청에 `isolated`를 명시해 격리한다. 실제 백엔드는 `isolation.backend`가 선택하며, 외부 캐시·서비스는 격리하지 않으므로 충돌 가능 리소스는 별도로 분리한다.
- 서브에이전트의 완료 보고는 산출물 수락이 아니다. 부모가 변경 파일과 계약 경계를 직접 다시 검증한 뒤 통합하며, `reviewer`·advisor의 판단은 실행 증거를 대체하지 않는다.
- `isolated` 작업의 성공 결과는 완료 시 부모 작업 트리에 자동 적용될 수 있다. 단계 일부만 맡은 작업이 다른 소유자의 호출부 수정이 필요한 시그니처를 바꾸면, 적용 직후 부모 트리의 제품 빌드가 깨지고 같은 트리에서 빌드 중인 다른 작업자가 원인을 오인한다. 이런 작업은 부모 트리가 빌드 가능한 상태로 끝나도록 범위를 정하거나 patch만 산출하게 하고, 적용 뒤에는 작업자의 suite뿐 아니라 부모 트리의 전체 제품 빌드로 확인한다. 이미 적용됐다면 patch로 보관한 뒤 되돌리거나 통합 담당자가 남은 호출부를 갱신해 부모 트리 빌드를 복구하고, 어느 쪽이든 동시 작업자에게 알린다. 다른 작업자의 변경을 함께 되돌리지 않는다.
- 대규모 작업은 계획 수립 후 배치 실행하고 체크포인트에서 검증하며, 실패한 계약에 의존하는 작업은 진행하지 않는다.
- 결과 자동 전달과 메시지를 이용하며 실행 중 반복 조회하지 않는다. 기다림·협의 경로는 [기본 도구의 백그라운드 작업](/tools/builtin.md)을 따른다.

## 에이전트 선택
- 역할별 에이전트와 사용 시점은 [에이전트 가이드](/agents/guide.md) 참조.
- 현재 세션의 가용 에이전트 목록에서 이름을 선택한다. `modelRoles`의 키는 모델 별칭이지 에이전트 등록이 아니므로 같은 이름의 에이전트가 있다고 가정하지 않는다. 가이드와 설치본이 다르면 실제 목록을 우선한다.
- 위임받은 에이전트도 작업 전 관련 OKF 개념을 확인하고 omp 기본 도구·스킬을 우선 사용한다.
