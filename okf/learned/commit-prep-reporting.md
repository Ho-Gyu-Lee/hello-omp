# 커밋 트리거

- 커밋은 사용자가 명시적으로 요청했을 때만 수행한다. 검증 통과·정리 완료·작업 종료는 커밋 트리거가 아니다.
- 요청 없이 커밋을 전제로 스테이징·메시지 준비를 진행하지 않는다.

# 준비 보고 내용

- 커밋 준비를 보고할 때 `git status --porcelain` 전체 목록을 그대로 제시한다. 이번 작업의 변경과 **무관한 변경(다른 작업·도구가 만든 수정, 미추적 파일)을 생략하지 않고 구분 표기**한다. 무관 변경을 함께 커밋할지는 사용자가 판단한다.
- 선별 스테이징으로 커밋할 때는 스테이징된 트리만으로 빌드·테스트가 통과하는지 확인한다: `git stash push --keep-index` → 검증 → `git stash pop`.
- 커밋 메시지는 해당 레포의 최근 로그 컨벤션(`git log --oneline`)을 따른다.

# 검증 명령

- 프로젝트에 검증 타깃이 있으면 개별 명령을 조합하지 말고 그것을 쓴다(예: `make check` = lint + fmt + vet + build).
