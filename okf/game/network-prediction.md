# 게임 네트워크 예측·보간·보정

상위 개념: [게임 네트워크 동기화](/game/network-sync.md#공통-원리)

## 예측·보간·보정
- 불연속 전환(teleport·respawn·scene transfer·authority change)마다 속도·보간 버퍼·오차 누적·timestamp·delta baseline과 서버 이동 검증의 기준점(last-good 위치·시간 예산)을 preserve·reset·recompute 중 하나로 명시한다. 서버가 위치를 직접 바꾸는 경로(지역 이동·인스턴스 입장)가 기준점 재설정을 건너뛰면 다음 정상 보고가 순간이동 위반이 된다.
- 외삽 뒤 보정을 움직이는 목표를 향한 1차 지연(lerp·지수 수렴)으로 하면 목표 속도에 비례하는 정상상태 오차(상수 gain이면 `e = v / k0`)가 남는다. 차이를 offset으로 저장해 `표시 = 목표 + offset`, `offset *= exp(-k·dt)`로 offset만 감쇠하거나 시간 상한이 있는 crossfade를 쓴다.

### 애니메이션·연출 시간
- 표시의 시간축과 연속성은 권위와 분리한다. 애니메이션 프레임 번호를 렌더 FPS나 전송 주기에 맞추는 것을 동기화로 보지 않고, 상태·동작 인스턴스 ID·시작 기준시각·지속시간·취소/사망 revision을 전달해 각 표시 타임라인에서 재생 위치를 계산한다. 원격 위치를 지연된 snapshot 시각으로 그리면 연출도 그 표시 시각에 맞추고, 수신 tick에 경과를 더하는 시계는 같은 재생 세대에서 단조로 두며 선행량에 상한을 둔다.
- 결과의 의미(처치 여부 등)는 보간 표본이나 클라이언트 추론에서 읽지 않고 결과 이벤트의 권위 표지로 싣는다. 표지가 없으면 처치 강조를 생략한다.

### 입력 처리 ACK와 로컬 재실행
- 서버는 권위 상태와 그 상태까지 처리한 입력의 경계를 함께 반환한다. Gateway·TCP ACK는 게임 로직 처리 완료가 아니고, 누적 ACK와 결과 확정은 같은 세션의 연속 prefix로만 진행하며 병합·거부·중복도 완료로 닫는다. prefix를 전제하는 소비자(저장 검증·결과 발행·재개)가 있으므로 불변조건을 완화하기 전에 소비자를 모두 열거한다(예: 취소가 앞선 미실행 명령 뒤의 대상을 미리 terminal로 닫으면 권위 프로세스가 fail-stop할 수 있다).
- 예측 복원 checkpoint는 같은 후속 입력에서 미래 동작을 결정하는 상태 전체를 담는다(예: 경로 재탐색은 동률 경로를 바꾸므로 최초 탐색 원점·목표·count/cursor·현재 leg를 보존한다).
- 명령을 예측 frame과 따로 즉시 보내면 RTT가 고정 step보다 짧을 때 결과가 그 명령을 담을 첫 예측 frame보다 먼저 돌아온다. 재실행은 아직 frame에 없는 명령과 권위가 이미 끝낸 명령을 구분해 끝낸 명령을 결과의 처리 tick에 재생하고, 로컬에서 먼저 건 효과(취소 즉시 정지 등)를 유지할지는 frame 순번 watermark가 아니라 그 명령 자신의 상태(frame·결과·snapshot 반영 여부)로 판정한다. watermark는 먼저 끝난 명령에서 멈춰 그 효과를 이후 모든 재실행에 남긴다(권위는 걷는데 예측은 정지해 표시가 정지 자세로 보정만 따라가고, 수락된 행동이 예측 타이머에서 빠져 같은 행동이 BUSY로 다시 나감).
- 귀환·자동 부활 같은 불연속(서버 tick이 일으키는 것 포함)에서는 명령 큐가 비었다는 사실로 입력이 정숙하다고 판단하지 말고 방향 상태·미ACK 이력·권위 대기열을 중립이게 하거나 epoch fence로 폐기하되, 중복 거절 기준(마지막 수신 sequence)과 처리 ACK는 유지해 재전송이 보류를 되살리지 못하게 한다.

### 원격 개체 보간
- 보간은 송신자가 정의한 상태 시각의 시간 도메인(`tick × step` 논리 시각인지 처리/송신 wall clock인지)을 따른다. 권위가 긴 frame의 초과 부채를 버리는데 표시 시계만 wall-clock 공백 전체를 진행하면 거짓 표본 부족과 지터 증가가 반복된다. 송신 주기와 복제 주기가 다르면(서버가 클라이언트 이동을 중계하는 경우 등) 받는 쪽의 파생 값(버퍼 시간·idle 판정·지터 창·예상 표본 간격)을 데이터를 생성한 쪽의 주기나 실측 간격으로 계산한다.
- 변경분만 보내는 복제(정지 중 무송신)에서는 침묵이 정상 정지와 끊김을 구분하지 못하므로 원격 타임라인 표본은 개체 변화와 무관하게 송신 주기마다 보내고 정지는 주기 keyframe·시간 표본의 부재로 판정한다. 전달 지터 표본은 수신 순서의 도착 간격으로 잰다(Mirror `SnapshotInterpolation`은 원격 시각 정렬 버퍼의 마지막 두 표본으로 계산해 뒤섞인 삽입에서 정확하지 않다고 주석으로 밝히며 `NetworkServer`는 tick별 `TimeSnapshotMessage`를 보낸다.
