# 게임 네트워크 예측·보간·보정

상위 개념: [게임 네트워크 동기화](/game/network-sync.md)

## 예측·보간·보정
- 외삽은 시간·거리·회전량 또는 도메인별 오차 예산으로 제한하고 권위 샘플 없이 무기한 진행하지 않는다.
- 보정은 의도된 별도 기준점이 없다면 현재 표시 상태에서 시작해 오래된 목표로 점프한 뒤 다시 이동하는 이중 보정을 피한다.
- teleport·respawn·scene transfer·authority change 같은 불연속 전환마다 속도·각속도·보간 버퍼·오차 누적·timestamp·delta baseline을 preserve·reset·recompute 중 하나로 명시한다. 서버 이동 검증의 기준점(last-good 위치·시간 예산)도 같은 전환 지점에서 다시 설정한다. 지역 이동·인스턴스 입장처럼 서버가 위치를 직접 바꾸는 경로가 이 재설정을 건너뛰면 다음 정상 보고가 순간이동 위반으로 판정될 수 있다.
- 정지·sleep·dirty 판정은 위치뿐 아니라 회전·애니메이션·상태 플래그 등 관찰 가능한 변화를 포함한다.
- 각도·주기 값은 비교와 delta 계산 전에 시스템이 정한 canonical representation 또는 shortest-path 규칙을 일관되게 적용한다. 누적 회전량이 의미 있는 값은 별도로 표현한다.
- 외삽·예측 뒤의 보정을 **움직이는 목표를 향한 1차 지연(lerp·지수 수렴)**으로 하면 목표 속도에 따라 커지는 정상상태 오차가 남는다. 수렴률이 `k0 + k1·e`이면 `e·(k0 + k1·e) = v`이고, 상수 gain(`k1 = 0`)이면 `e = v / k0`라서 `k0 = 8/s`, `v = 4 m/s`에서 0.5 m다. 이보다 작은 고정 복귀 거리는 이동하는 동안, 작은 회전 오차 조건은 회전하는 동안(지연 약 `ω / k`) 충족되지 않아 보정 상태가 정지나 다음 끊김까지 이어진다. 보정 시점의 차이를 offset으로 저장해 `표시 = 목표 + offset`, `offset *= exp(-k·dt)`처럼 offset만 감쇠하거나 시간 상한이 있는 crossfade를 쓴다. 고정 속도 이동 중 표본 하나를 빠뜨린 뒤 정해진 시간 안에 보간 상태로 돌아오는지 검사한다. 곡선 경로에서 늦게 도착한 표본이 빈칸을 채워 보간 쌍이 바뀌면 경로와 현(chord)의 차이만큼 순간 이동할 수 있으므로 같은 offset 감쇠를 검토한다(실행으로 재현하지 않은 기하학적 추론).

### 애니메이션·연출 시간
- 애니메이션 프레임 번호를 렌더 FPS나 위치 전송 주기와 일치시키는 것을 동기화로 보지 않는다. 상태·동작 인스턴스 식별자·시작 기준시각/처리 경계·지속시간/재생률·취소/사망 revision 중 실제 동작에 필요한 정보를 전달하고 각 표시 타임라인에서 재생 위치를 계산한다. 모든 루프 클립의 위상을 서버가 반드시 복제해야 한다는 뜻은 아니다.
- 원격 위치를 지연된 snapshot 시각으로 그린다면 애니메이션·연결된 월드 연출도 그 표시 시각에 대응시킨다. 패킷 도착 시점부터 무조건 0번 프레임으로 시작하지 않으며, 지연 도착·중복·취소·관찰 재진입에서 현재 위상과 일회 효과의 소비를 구분한다.
- 보행 루프는 의미상 이동 시간이나 누적 이동 거리에서 위상을 구하는 방식을 검토한다. 위치 보정용 시각 오프셋을 실제 보행 거리로 누적하지 않는다. 정상 정지·벽에 막힘·입력 부족·보간 표본 부족을 같은 idle 전환으로 처리하지 않고, 의도·실제 변위·데이터 신선도에 따라 위상 유지/정지와 전환 정책을 명시한다.
- 시각 residual만 제외해도 예측 base 자체가 reconciliation으로 바뀌면 보행 거리가 튈 수 있습니다. 보행용 연속 좌표를 `base + offset`으로 분리하고 soft 복원 뒤 `offset = 이전 보행 좌표 - 새 base`로 다시 정합니다. 중첩 취소→replay에서 offset을 누적 가산하지 않으며 진짜 이동·step 사이 보간은 유지합니다. 이 좌표를 충돌·권위 위치로 역주입하지 않고 hard 불연속/새 설치에서 기준을 초기화합니다.
- 수신 tick에 수신 후 경과를 더하는 액션 시계는 같은 tick 재수신만으로도 역행할 수 있습니다. 같은 재생 세대에서는 단조성을 유지하되 샘플 이후 선행량에 상한을 두고 비활성 세션에서는 멈춥니다. 무제한 wall-clock 외삽값에 `max`만 적용하면 긴 공백의 앞선 시각에 붙잡힐 수 있습니다. 상태를 바꾸는 새 full-state 설치와 중복 응답을 구분해 시계 원점을 처리하고, 표시 시계로 권위 판정 시간을 바꾸지 않습니다.
- 최신 자기 HP/피격을 수신 시각에 표시하고 원격 공격/투사체를 버퍼 시각에 표시하는 정책은 그림 사이의 시차를 만듭니다. 권위 상태 오류와 이 표시 절충을 구분하고, 엄격한 동시 표시가 요구될 때만 관련 HUD·액션·효과를 함께 같은 시각 정책으로 옮깁니다.
- 표시 시차를 판단할 때 지터 버퍼의 목표 깊이와 실제 시차(원인 사건의 적중 tick 대비 각 표시가 그 사건을 보여 준 시각)를 구분해 측정합니다. 측정 조건(주입 RTT·지터)을 함께 남기고 버퍼 깊이를 체감 지연으로 보고하지 않습니다. 공개된 상용 자료는 소유자 입력 피드백 예측·원격 보간·권위 판정의 분리는 설명하지만 자기 HP·피격을 어느 시간축에 표시하는지는 거의 밝히지 않으므로 이는 근거로 확정된 업계 기본값이 아니라 제품 선택입니다. 가해 측 명중 A/V 예측(예: [CS2 2024-11-13 damage prediction](https://store.steampowered.com/news/app/730/view/4458095069430284352))과 피해자 측 연출(예: [CS2 2026-04-21 aim punch](https://www.counter-strike.net/newsentry/508485755865137153))을 같은 근거로 섞지 않습니다. 자기 동작 연출을 예측으로 앞당기면 버퍼 시각에 남은 자기 투사체·명중 연출과의 시차가 커지므로 해당 연출의 시간축도 함께 정합니다.
- 엔진의 자동 애니메이션이 scaled delta로 진행하는지 확인한다. 게임 이동을 독립된 단조 시간으로 실행해도 자동 재생은 엔진 배속·pause에 영향을 받을 수 있다. 서버 현재·로컬 예측·지연 보간은 서로 다른 시각이므로 같은 벽시계 순간의 그림 프레임을 강제로 일치시키지 않는다.
- 파라미터와 상태(state·시작 시각) 중 하나를 원격 애니메이션 표시의 정본으로 정한다. 상태를 정본으로 쓰면서 원격 상태 머신이 복제된 파라미터로 자체 전이도 일으키면, 뒤이어 도착한 상태를 적용할 때 튀거나 일회 연출이 중복될 수 있다(실행으로 재현하지 않은 추론). 이 경우 원격 개체의 파라미터 기반 자동 전이를 끈다. 파라미터는 위치 index가 아니라 공유 스키마의 ID로 식별하며(중복은 생성 단계에서 실패), 빌드가 달라 schema가 다르면 버전 불일치로 거부하고 같은 빌드에서 어긋난 상태만 full-state 재동기화로 복구한다. 상태 delta에는 순서 번호를 붙이고, 낮은 주기의 전체 상태 snapshot으로 유실·지각 표본을 자가 복구하되 snapshot이 일시정지 같은 로컬 표시 정책을 덮어쓰지 않게 한다.
- 공격·피격·스킬·사망의 판정은 권위 상태 전이와 시간 계약이 결정한다. 애니메이션 콜백·프레임 도달·소리 재생이 피해나 자원 소비를 확정하지 않는다. 예측 연출은 재실행 시 중복 부수효과를 막고 거부/취소에 대응하며, root motion·대시·넉백이 게임 위치를 바꾼다면 서버가 검증할 이동 규칙과 분리하지 않는다.
- 지연 표시 시각에 도달한 일회 결과 이벤트(피해 등)로 연출 강도를 고를 때, 그 판단에 필요한 상태(처치 여부 등)를 같은 순간의 **보간 하한 표본**에서 읽지 않는다. 30Hz 권위 tick을 10Hz snapshot으로 보내면 두 표본 사이 tick의 처치 피해는 이벤트 tick에 재생되지만 보간 표본은 아직 생존이고, 이벤트는 한 번 소비되므로 다음 표본에서 사망을 봐도 처치 연출이 빠진다. 처치 여부는 결과 이벤트 자체에 실린 권위 근거로 판단한다.
  - "사망 tick = 이벤트 tick"은 같은 tick의 여러 타격 중 **누가 처치했는지**를 가리지 못한다.
  - 클라이언트 쪽 추론은 모두 오귀속 경로가 남는다.
    - 한 프레임에 소비한 이벤트 묶음의 끝은 tick의 끝이 아니다. snapshot당 이벤트 상한과 미확인 이벤트 재전송 때문에 같은 tick 이벤트가 여러 snapshot에 걸칠 수 있다.
    - 서버가 버린 이벤트의 누적 카운터는 표시 시점에 읽으면, 내 타격을 이미 받은 뒤에 버려진 다른 공격자의 처치타를 놓친다.
    - 정확한 귀속에는 처치자·치명타 표지가 필요하다. 추론하려면 이벤트 수신 시점에 기록한 완결 경계가 있어야 한다.
  - 그런 근거가 없으면 확인할 수 없는 처치 강조를 추측하지 말고 생략한다.
  - 2026-10-16 실제 작업에서 사망 tick 비교, tick 완결 추론, drop 카운터 비교를 차례로 넣었다. 외부 검토가 매번 남은 오귀속 경로를 찾아, 처치 전용 강조를 제거하고 권위 표지를 선행 조건으로 남겼다.
- 히트스톱·카메라 흔들림처럼 표시 전용 효과는 권위 시간이나 전역 time scale을 멈추지 않고 해당 개체의 표시 프레임·카메라 offset만 바꾼다.
  - 추종 카메라 위치와 시야 clamp 계약을 흔들림 offset과 분리한다.
  - 줌·viewport 변경처럼 clamp 기준이 바뀌는 경로에서도 진행 중인 흔들림 offset을 같은 호출에서 다시 계산한다.


### 입력 처리 ACK와 로컬 재실행
- 입력 예측이 필요한 게임에서는 서버 검증 가능한 입력과 session generation·sequence를 보내고 클라이언트에 미확정 입력을 제한된 크기로 보관한다. 클라이언트가 보낸 위치·delta time·timestamp·명중 신고 자체가 권위 상태는 아니다.
- 서버는 권위 상태와 **그 상태까지 처리한 입력의 경계**를 함께 반환한다. Gateway의 수신/전달 ACK나 TCP ACK를 게임 로직 처리 완료로 해석하지 않는다.
- 누적 ACK를 쓰려면 같은 세션의 순서가 확정된 입력 prefix여야 한다. 수락과 거부 결과를 구분하고 거부 입력은 상태에 적용하지 않되 클라이언트가 해당 예측을 폐기할 수 있게 한다. 누락/역순 입력을 건너뛰고 큰 sequence 하나를 처리 완료 경계로 삼지 않는다.
- 병합·접수 거부·중복도 완료 의미를 정의한다. 이미 sequence를 가진 입력을 병합할 때는 대체 완료 등 명시적인 결과로 처리 경계를 닫고, 큐에서 단순 삭제해 ACK 구멍을 만들지 않는다. 접수 전 번호 부여 여부와 실패 시 pending 정리 정책을 정하며, 이미 전송한 번호는 timeout만으로 다른 요청에 재사용하지 않는다. 중복은 기존 pending/완료 결과를 재사용하고 다시 실행하지 않는다.
- 취소 명령(이동 취소·전체 취소)은 대기열 전체를 미리 보고 앞선 명령을 무효화하되, **결과 확정은 sequence 순서로만** 진행한다. 실행 예산(틱당 실행 수)이 소진된 미취소 명령 뒤의 취소 대상까지 미리 terminal로 닫으면 "terminal은 연속 prefix" 전제를 쓰는 영속 저장 검증·결과 발행(issued) 경계·재개 창이 그 상태를 거부해 권위 프로세스가 fail-stop할 수 있다. 취소 fence 자체를 대기열에 남겨 다음 틱에 이어서 적용하고, 같은 틱의 행동+전체 취소는 실행 전에 막는다. 한 계층의 불변조건을 완화하려면 codec·저장·ACK·재개 소비자 전체를 먼저 열거한다(독립 리뷰 3건이 같은 결함을 서로 다른 소비자에서 확인).
- 클라이언트는 ACK까지의 확정된 입력을 제거하고, 받은 권위 상태를 예측 기준으로 삼아 미확정 입력만 순서대로 재실행한다. 재실행이 발사 요청·소리·재화 변경을 중복 발생시키지 않도록 표시/외부 부수효과와 시뮬레이션을 구분한다.
- 예측 복원 checkpoint에는 같은 후속 입력에서 미래 동작을 결정하는 상태가 들어 있어야 합니다. 위치·최종 목적지 또는 다음 waypoint부터 suffix를 다시 탐색하면 시작점 접속·동률 경로가 달라져 보정이 반복될 수 있습니다. 전체 경로를 복제하지 않더라도 최초 탐색 원점·목표·전체 count/cursor·현재 leg처럼 같은 정규 경로를 재구성하고 검증할 정보를 보존하고 동등성 비교에도 포함합니다. 초기 중심 생략과 보정 후 첫 leg를 구분합니다. 아날로그 방향은 공격 facing이나 입력 부족의 출력 속도로 대체하지 않습니다.
- 복원에 쓰는 경로 cache는 불변 world/geometry·이동 정책·최초 원점·목표가 일치해야 합니다. 정지 뒤 남은 cache나 별도 validator의 hint도 동일하게 검사하고, cursor/waypoint/count 검증이 끝나기 전에 live 경로를 덮어쓰지 않습니다. cache miss의 재탐색 실패·scratch 부족은 이전 유효 이동을 보존하며, 다른 world/정책의 hint 거부와 실제 후속 이동을 함께 검사합니다. 반복 복원에서 같은 탐색을 다시 하거나 고정 최대 경로 전체를 불필요하게 복사하지 않습니다.
- 정상 snapshot에서 입력 프레임 ACK와 명령 완료 ACK를 함께 보내면 각각의 송신 최대값뿐 아니라 **같은 실행 입력 prefix에 속하는 조합인지** 검증한다. terminal 폐기 경계는 [복구·전달 의미론](/game/network-delivery.md#복구전달-의미론)의 terminal 장애 항목처럼 실제 적분 경계와 별도로 검증한다. 이력을 제거한 뒤에도 마지막 ACK의 기준 상태를 별도로 유지하여 같은 ACK의 새 권위 보정과 동일 보정의 중복을 구분한다. 메시지·완료 결과·checkpoint 전체를 검증한 뒤 한 번에 baseline·이력·게임 상태를 반영한다.
- RTT 길이만으로 이력을 자르는 것과 서버가 처리한 입력을 식별하는 것은 다르다. 지터·서버 큐 대기·입력 거부가 있는 경로에서 시간 추정으로 ACK를 대체하지 않는다.
- 같은 이동 코드를 양쪽에서 사용해도 timestep·충돌 환경·다른 개체 상태·부동소수점 차이로 예측은 틀릴 수 있다. 임의 물리 엔진 간 결정성을 가정하지 않는다. 이력 상한을 넘거나 필요한 입력이 없으면 무한 재실행 대신 권위 상태로 재동기화한다.
- 아날로그 조향처럼 연속 갱신되는 조작은 순서 번호와 완료 결과를 가진 명령보다 **tick별 절대 입력 상태**로 보내는 편이 안전하다. 명령 창 고갈·결과 폭증·결과 때문에 강제된 snapshot을 피하고, 폐기된 입력이 있어도 다음 상태가 스스로 완전하다. 목적지·공격·취소 같은 이산 의도만 명령으로 둔다. 서버와 예측이 같은 프레임 적용 순서(예: 명령 → 방향 상태 → 적분)를 공유하고, 한쪽만 실행할 수 있는 조건(예: 방향 중 목적지 거부)도 같은 함수에 둔다.
- 서버가 수신 시각에 적용하는 제어 효과가 클라이언트 예측에서 재현될 수 없다면 parity가 깨진다. 수신 시점 효과는 이미 대기 중인 명령의 취소처럼 클라이언트도 알 수 있는 결과로 제한하고, 이동 정지는 해당 프레임 안의 명령 위치에서 양쪽이 같게 적용한다. 입력 부족 hold가 0으로 만든 속도처럼 이후 계산에 쓰이지 않는 출력 전용 필드는 재실행 필요 판정에서 제외한다.
- 서버 입력 버퍼 깊이는 클라이언트의 입력 생성률을 미세 조정해(예: 0.9–1.1배) 목표 여유로 유지할 수 있다. 서버 보고는 과거 상태이므로 **보고 이후 이미 적용한 보정량을 차감**해야 하며, 이를 빼면 RTT가 길 때 한계 순환으로 발산한다. 소비된 입력이 없는 구간은 "표본 없음"으로 보내 추정치를 유지한다. 오래된 명령 없는 입력의 강제 제거는 추가 이동권을 주지 않는 복구 수단이지만, 제거된 입력만큼 입력 ACK가 tick보다 앞설 수 있다는 불변식을 클라이언트 검증에 함께 반영한다.
- 같은 세션의 귀환처럼 **옛 입력이 새 위치에 적용되면 안 되는 불연속 전환**에서는 명령 큐가 비었다는 사실만으로 입력이 정숙하다고 판단하지 않습니다. 명령 창 용량(credit)을 쓰지 않는 방향 상태의 현재 값·미ACK 이력·권위 대기열까지 중립이어야 하며, 그렇지 않으면 명시적인 세션/epoch fence로 옛 입력을 폐기합니다. 경로 폐기가 필요한 전환은 보정 전에 경로를 정지합니다. 권위 표본 설치까지 새 입력을 보류하는 계약에서는 같은 세션 세대 안에서 보류 시작 시 기록한 목표 불연속 식별자와 같거나 이후인 표본이 설치될 때만 hold를 해제합니다. 그보다 이전의 중간 표본에서는 불연속 카운터가 증가했더라도 해제하지 않습니다. 식별자 wrap은 프로토콜의 순서 비교 규칙을 따릅니다. disconnect/resync는 hold를 정리하되 full-state 설치를 마치기 전(READY 전)의 입력은 계속 거부합니다.
- 서버 tick이 스스로 일으키는 불연속(자동 부활 등)도 같은 입력 폐기 대상입니다. 명시적 귀환·재개 경로만 보류 입력을 비우면, 사망 중 입력 유지 시간 안에 받은 방향 입력이 부활한 개체를 부활 tick에 바로 움직입니다. 보류 입력을 버릴 때 중복 거절 기준(마지막 수신 sequence)과 처리 ACK는 그대로 둡니다. 그래야 버린 입력에 ACK가 생기지 않고 재전송이 hold를 되살리지 못하며 이후의 새 입력만 이동시킵니다. 위치 보정이 실패한 경로는 재시도 때까지 입력을 유지하고, 명령 대기열·목적지 경로는 이 폐기와 별개로 다룹니다(2026-10-11 실제 결함, 회귀 테스트로 확인).

### 원격 개체 보간과 판정 지연 보상
- 자기 캐릭터의 예측/보정, 다른 개체의 snapshot 보간, 서버의 명중 판정 지연 보상은 서로 다른 기능이다. 원격 개체는 수신한 권위 샘플 사이의 표시 시각으로 보간하고, 샘플 부족에는 제한된 외삽/정지/재동기화 정책을 적용한다.
- 시뮬레이션 틱·복제 송신 주기·렌더 프레임의 구분과 타 제품 수치의 비채택은 [게임 시간 계층과 권위](/game/network-time-movement.md#게임-시간-계층과-권위)를 따른다.
- 주기 상향의 비용과 이득을 따로 산정한다. 비용은 **CPU(초당 tick 작업량), uplink(입력 메시지 생성률), downlink(복제 주기 × 관찰 대상 수 × 대상당 bytes)**로 나눈다. tick 주기와 입력 주기를 1:1로 묶으면 CPU뿐 아니라 uplink도 tick에 비례하고, snapshot 주기가 분리돼 있으면 tick만 낮춰도 downlink는 줄지 않는다. 관찰자별 복제 대상 선정·정렬·직렬화 비용은 관찰자 수와 후보 수에 따라 늘어나므로 시뮬레이션 tick 비용과 따로 측정한다. 이득은 입력이 각 고정 스텝 경계를 기다리는 시간이 단계마다 최대 한 틱 간격만큼 줄어드는 것이다. [Apex Legends 서버·넷코드 설명(2021-04-28, 조회 2026-09-29, 재확인 2026-10-15)](https://www.ea.com/games/apex-legends/apex-legends/news/servers-netcode-developer-deep-dive)의 "20→60 Hz는 대역폭·CPU 3배, 최선 약 2프레임 단축"은 **tick마다 전체 월드 상태를 복제하는 모델**의 계산이며 다른 복제 모델에 그대로 적용하지 않는다. 프로토타입·엔진 기본 고정 스텝을 제품 서버 주기로 간주하지 않고, 목표 밀집도의 tick 꼬리 지연·AOI fanout·메시지/패킷 수와 조작 수락 기준을 함께 측정해 주기를 고른다.
- 입력 프레임과 권위 step을 1:1로 대응시키는 구조에서 서버 주기만 낮추면 입력 큐가 매초 두 주기(Hz)의 차만큼 증가한다. 클라이언트 입력·예측 주기를 함께 바꾸거나 입력 시간을 권위 step에 대응시키는 규칙을 먼저 정의한다.
- 원격 보간은 송신자가 정의한 **상태 시각의 기준 시계**(시간 도메인)를 따라 진행합니다. 상태 시각이 `tick × step`인 논리 시각인지 처리/송신 wall clock인지 확인하고 서로 같다고 가정하지 않습니다. 권위가 긴 frame의 초과 부채를 버리는데 표시 시계만 wall-clock 공백 전체를 진행하면 거짓 표본 부족과 지터 증가가 반복될 수 있습니다. 동일 호스트의 실행 예산을 확실히 아는 경로에서만 그 정체를 별도 흡수하고 전달 지터 표본과 분리하며, 일반 원격 연결의 client frame 지연을 서버 시간 정지로 간주하지 않습니다.
- 개체별 불연속은 그 개체의 버퍼만 재설정하고 공유 타임라인을 되감지 않습니다. 버퍼 포화에는 최신 표본 거부보다 가장 오래된 표본 제거가 안전한 경우가 많습니다. 새 세대에서는 타임라인과 지연·drift·재생률을 함께 초기화합니다. 조정 계수 자체를 고정하는 검사 대신 실제 burst/slow 전달에서 빨라짐/느려짐, 동적 buffer 경계와 비중립 재생률에서 새 세대 복구를 검사합니다. 원격 HP·사망·공격 같은 계단 상태도 해당 원격 표시 시각에 샘플링합니다.
- 클라이언트 송신 주기와 서버 복제 주기가 다르면, 받는 쪽의 파생 값(버퍼 시간·timestamp 보정·idle 공백 판정·지터 EMA 창·예상 표본 간격)을 그 데이터가 **생성된 쪽의 주기**나 실측 표본 간격으로 계산합니다. 클라이언트가 보낸 이동을 서버가 받아 관찰자에게 중계하면 관찰자 기준의 표본 간격은 서버 복제 주기가 아니라 원 송신자의 주기입니다. 전역 주기 하나나 직전 송신자의 주기를 쓰면 버퍼가 잘못 잡히고, 예상 간격에 걸린 분기(예: 고차 보간 사용 조건, 공백 재설정 임계값)가 조용히 꺼지거나 정상 지터에 발동합니다.
- **변경분만 보내는 복제(정지 중 무송신)**는 다음 경계를 따로 다룹니다. ① 원격 타임라인 표본은 개체 변화와 무관하게 송신 주기마다 보냅니다(빈 시간 표본·tick header). 개체 갱신에만 시각이 실리면 모두 정지한 구간에 시계 표본이 끊깁니다. ② 비신뢰 채널로 보낸 마지막 "정지" 갱신이 유실되면 수신측은 이전 속도로 외삽한 위치에 머물 수 있습니다. 마지막 상태를 신뢰 경로나 반복 송신으로 보내거나 낮은 주기의 전체 상태(keyframe)를 유지하고, 축별 변경 플래그 delta도 주기적인 전체 상태로 baseline을 다시 맞춥니다. ③ 정지 뒤 첫 갱신 시점의 버퍼에는 오래된 표본 하나만 남아 있어 그대로 보간하면 정지 구간을 가로질러 미끄러집니다. 새 표본의 한 주기 전 시각에 현재 표시 자세를 다시 심고 시작합니다. ④ 전달 지터 표본은 수신 순서의 도착 간격으로 잽니다. 원격 시각으로 정렬한 버퍼의 마지막 두 표본의 도착 시각 차를 쓰면 역순 도착 때 음수·중복 표본이 들어갑니다([Mirror `SnapshotInterpolation`](https://github.com/MirrorNetworking/Mirror/blob/c4f3739966e151f405be1762d33502794fd034ff/Assets/Mirror/Core/SnapshotInterpolation/SnapshotInterpolation.cs)은 이 방식을 쓰며 뒤섞인 삽입에서 정확하지 않다고 주석으로 밝힙니다). ⑤ 무수신 시간으로 정지·freeze를 판정하지 않습니다. 정상 정지와 끊김이 같은 침묵이 되므로 주기 keyframe·시간 표본의 부재로 판단합니다. 근거: [Mirror 고정 소스](https://github.com/MirrorNetworking/Mirror/blob/c4f3739966e151f405be1762d33502794fd034ff/Assets/Mirror/Core/NetworkServer.cs)의 tick별 `TimeSnapshotMessage` 송신, [`NetworkTransformReliable`](https://github.com/MirrorNetworking/Mirror/blob/c4f3739966e151f405be1762d33502794fd034ff/Assets/Mirror/Components/NetworkTransform/NetworkTransformReliable.cs)의 `NeedsCorrection`·`RewriteHistory`(조회 2026-10-11). ②는 실행으로 재현하지 않은 추론입니다.
- 과거 명중 판정이 필요한 전투만 서버가 보유한 제한된 권위 이력으로 검사한다. 클라이언트 발사 시각은 검증 가능한 시계 대응·허용 rewind 범위·현재 권한/발사 조건으로 제한한다. 엄폐 후 피격 같은 공정성 대가도 게임 정책으로 정한다.
- 지연 보상은 게임 전체·경제 상태의 무제한 rollback이 아니다. Gateway가 명중 여부를 결정하거나 클라이언트가 보고한 과거 상태를 정본으로 삼지 않는다.
- 시각적 수렴 알고리즘을 이식할 때 빈 이력·0/비유한 시간·보간 계수 범위·각도 wrap·teleport와 이동 종료를 검증한다. 특정 게임의 수렴 상수 하나로 모든 이동 모델을 해결하지 않는다.
