# 게임 서버 기능/성능 체크리스트

공통 메모리·동시성·프로토콜·큐 상한은 [서버 운영](/development/server-checklist.md), 메시지별 전달/혼잡은 [네트워크 전달](/development/network.md), 상태 수락·정보 가시성은 [게임 보안](/security/game.md), 권위 이전·baseline은 [복구·전달 의미론](/game/network-delivery.md), 결과 공개와 내구성은 [영속화·장애 체크리스트](/game/server-persistence.md)를 따른다.

## Gateway와 로직 스레드의 분리

아래는 Gateway를 두고 로직 실행을 소유 단위별로 나누는 구조를 선택한 서버의 설계·검증 기준이며, 모든 게임의 필수 구조나 특정 서비스의 내부 구현을 주장하지 않는다. 로직 스레드 수(단일·멀티 로직 스레드)는 [사용자 개발 방향](/direction.md#동시성과-서버-구조)을 따른다.

| 경계 | 책임 | 하지 않는 일 |
|---|---|---|
| Gateway | 클라이언트 연결·프레이밍·인증된 세션 결합·라우팅·송수신 큐·브로드캐스트 팬아웃 | 이동·피해·재화·아이템의 권위 판정 |
| 로직 스레드(소유 단위별) | 소유 월드/존/인스턴스의 상태 변경, 명령 검증, 이동·전투·AI·퀘스트, 공개 가능한 결과와 수신 대상 결정 | 소켓 송신 완료·DB·파일 I/O의 동기 대기 |
| I/O 작업자 | Gateway 연결·DB·파일 작업, 완료 메시지 전달 | 로직 스레드 소유 객체의 직접 변경 |

- [ ] **소유 단위별 단일 작성자**를 명시한다. 단일 로직 스레드는 모든 소유 단위를 한 스레드가, 멀티 로직 스레드는 존·샤드 같은 단위를 스레드별로 소유하며 둘 다 이 원칙 위에서 성립한다. 서비스 전체가 하나의 스레드라는 뜻도 게임 서버에 네트워크 I/O가 없다는 뜻도 아니다. 확장해도 같은 객체를 여러 소유자가 동시에 변경하지 않는다.
- [ ] Gateway와 콘텐츠 서버 사이에 명시적 메시지 경계를 두고 별도 hop·큐잉·직렬화 비용을 측정한다. Gateway는 접속·송신 병목을 분리할 뿐 콘텐츠 계산을 병렬화하지 않으므로 포화된 단일 존의 전투 계산은 Gateway 추가로 빨라지지 않는다. 존/인스턴스 배치·입장 제한·소유권 분할(로직 스레드 분할 포함) 중 요구에 맞는 정책을 정하고 교차 경계 정합성을 검증한다. 콘텐츠 서버는 Gateway가 전달했다는 이유로 이동·충돌·경제 결과를 신뢰하지 않으며 비공개 네트워크 배치만으로 내부 peer 인증·인가를 대신하지 않는다.

## 큐·브로드캐스트·성능

- [ ] 수용 인원은 종단 지연과 전체 loop 포화로 판정하며 snapshot 수신 신선도나 tick 시간·DB commit 지연만으로 판정하지 않는다(예: snapshot은 100ms 안에 도착해도 입력 처리 경계(ack)는 로직 스레드 CPU 포화로 수 초 밀릴 수 있다). 세션별 미확인 입력 수(또는 입력→처리 지연)·RTT·로직 스레드 CPU·loop 구간별 시간을 최악 밀집 장면에서 재고, 포화 구간은 비용 양상이 다른 하위 구간(예: 세션 순회와 snapshot 생성)으로 나눠 계측한 뒤 개선한다. 외부 연결 상한은 World 수 × 정원 + 인증·재접속·전환 여유에서 도출한다(World 하나의 정원과 같으면 그 World가 가득 찼을 때 다른 지역 접속까지 막힌다).
- [ ] AOI는 후보(성능)·인가(보안)·우선순위(상한)·관측(시험)을 구분한다. 공유 후보 목록은 최종 인가 목록이 아니다. 격자 AOI는 이탈 반경을 진입 반경보다 크게 두되(히스테리시스) 후보를 3×3 검사 결과에서만 다시 만들면 그 효과가 사라지고, 관찰 관계는 양방향으로 갱신하며(이동한 개체를 "보는 쪽"만 계산하면 새로 보게 될 정지 NPC가 늦게 나타난다), 관찰 집합을 거치지 않는 전역 broadcast는 공개 범위를 우회하므로 spawn 상태에 포함한다. 복제 개수 상한의 초과 후보는 게임 요구로 우선순위를 정하고(거리순만 쓰면 밀집 사냥터에서 근처 플레이어·파티원이 사라진다), 누락 시험은 관찰자 snapshot이 상한까지 찼는지 함께 기록해 설계상 밀려난 경우와 복제 결함을 구분한다([Unreal Replication Graph](https://dev.epicgames.com/documentation/en-us/unreal-engine/replication-graph-in-unreal-engine)).
