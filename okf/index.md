# OKF Knowledge Bundle

사용자의 방향과, 모델이 틀리기 쉬운 비자명 사실만 담는 번들이다. 일반 지식은 담지 않는다(기준: [OKF 학습 축적](/learning/accumulation.md)). 작업에 맞는 개념만 골라 읽는다. 링크는 번들 루트 기준이다.

## 방향과 규칙
* [사용자 개발 방향](/direction.md) - 프로필, 코드 표기, 멀티스레드·MMORPG·MSA·단일 로직 스레드 관점, 설계·작업 방식의 정본. 설계 판단과 선택지가 여럿일 때.
* [언어 공통 코딩 스타일](/language-style.md) - 네이밍·배치·빈 줄·줄바꿈 선택과 언어별 예외. 모든 언어의 코드 작성·리뷰 전에.
* [C/C++ 전용 코딩 규칙](/language-style-c-cpp.md) - C/C++ 표기·switch·접근 순서·C 이름·헤더 선택. C/C++ 코드에서 함께.
* [코딩 스타일](/coding-style.md) - 요청 범위·계약·비용 보존, 구현 결정 사다리, 확장점 금지, 변경 쉬운 구조, 반복 실수를 일반화한 근본 원리.
* [버그 수정 원칙](/bugfix.md) - 결함 클래스 수정, 이전 수정과 새 케이스의 동시 만족, YAGNI 경계.
* [워크플로](/workflow.md) - 검증(테스트 우선·실패 확인·무결성), 수락 기준, 작업 파일 위치·검증 산출물 보존, 검증 대상 동일성, 독립 검토, 컨텍스트 재개.
* [응답 원칙](/response-principles.md) - 범위, 질문과 요구 정렬, 옵션 제시, 보고 매체, 검토 후 통합 최종본.
* [정확성](/accuracy.md) - 확인과 에스컬레이션, 버전 의존 사실, 도달 가능한 상태.
* [OKF 학습 축적](/learning/accumulation.md) - 기록 판정 세 질문, 실수의 원리화, 기록 위치(공개·로컬·프로젝트 레포), 반영·보고.
* [프로젝트 지도와 작업 동기화](/project-navigation.md) - `프로젝트 지도: 유지` 선언 프로젝트의 갱신·게시 계약.
* [프로젝트 지도 화면 설계](/project-map-design.md) - 지도 화면의 구성·글·디자인·칸반 기준.
