# OKF Knowledge Bundle

사용자의 방향과 모델에 부족한 지식(학습에 없거나 바뀐 사실, 환경 특이점, 실무에서 자주 놓치는 판단 기준)을 담는 번들이다. 모델이 이미 정확히 아는 일반 지식은 담지 않는다(기준: [OKF 학습 축적](/learning/accumulation.md)). 작업에 맞는 개념만 골라 읽는다. 링크는 번들 루트 기준이다.

## 방향과 규칙
* [사용자 개발 방향](/direction.md) - 모델 기본값 대신 따를 사용자의 선택 — 프로필, 코드 표기, 멀티스레드·MMORPG·MSA·단일 로직 스레드에 대한 관점, 설계와 작업 방식. 설계 판단이나 선택지가 여럿일 때 읽는다. 다른 문서는 이 방향을 재진술하지 않고 링크한다.
* [언어 공통 코딩 스타일](/language-style.md) - 모든 언어의 코드 작성·리뷰 전에 읽는 정본입니다. 적용 우선순위, 네이밍 기본값과 언어별 예외, 배치·줄 접기·빈 줄·제어 흐름 선택을 정하고, C/C++ 추가 선택은 C/C++ 전용 규칙에 둡니다.
* [C/C++ 전용 코딩 규칙](/language-style-c-cpp.md) - C/C++ 코드 작성·리뷰 때 언어 공통 코딩 스타일과 함께 읽습니다. C/C++에만 적용하는 기본 표준·표기·switch·접근 순서, C 이름·상수, include·헤더 보호·정적 등록, Godot 확장 이름 선택입니다.
* [코딩 스타일](/coding-style.md) - 요청 범위·계약·비용 보존, 구현 결정 사다리, 반복 실수를 일반화한 근본 원리, 공개 API와 선제적 확장점 금지, 다음 변경이 쉬운 구조(깊은 모듈), 서버 타입 접미사 어휘와 스타일 정본 연결.
* [버그 수정 원칙](/bugfix.md) - 결함 클래스 수정, 계약 경계에서 자른 영향 범위, 이전 수정과 새 케이스의 동시 만족(롤백 금지), 참조 구현 수정의 이식 판정, 소비자 계약 회귀 방지, YAGNI 경계.
* [워크플로](/workflow.md) - 검증과 실행 증거(테스트 우선·기존 테스트 확장 우선·실패 확인·검증 무결성과 테스트 통합의 경계), 수락 기준, 작업 파일 위치와 검증 산출물 보존, 검증 대상의 동일성, 위험에 비례한 독립 검토와 구현 전 설계 검토의 대상·상한, 중단 지시와 컨텍스트 재개.
* [응답 원칙](/response-principles.md) - 범위·확장 억제, 비한정 예시 해석, 질문과 요구 정렬, 비차단 작업 공유, 옵션 제시, 함축성, 커뮤니케이션 스타일, 보고 매체 선택, 검토 후 통합 최종본.
* [정확성](/accuracy.md) - 가용 수단을 다 쓰기 전 확인 불가 금지와 에스컬레이션 사다리, 버전 의존 사실의 확인·정정, 외부 인기·평가 자료의 해석 한계, 신뢰도 표시, 도달 가능 상태 처리.
* [OKF 학습 축적](/learning/accumulation.md) - 무엇을 기록하는지(사용자 방향과 모델에 부족한 지식)와 판정 시점·기록 판정 세 질문·보류 사유의 한계, 실수를 원리로 일반화하고 고친 원리 문장의 효과를 비용에 맞게 확인, 기록 위치(공개 소스·로컬·프로젝트 레포), description을 정본으로 한 index 반영·검증·배포와 기록·보류 보고.
* [프로젝트 지도와 작업 동기화](/project-navigation.md) - `프로젝트 지도: 유지` 선언 프로젝트에서 코드·설정·문서를 바꿀 때 읽는 계약 — 비차단 변경 위치 공유, 지속 프로젝트 지도의 적용·중지·삭제, 문서 배치·목차·상태·계획, Archify 기술 계약, 작업 트리 근거·신선도, 검증 후 게시 절차와 완료 보고. 화면 기준은 프로젝트 지도 화면 설계가 정본이다.
* [프로젝트 지도 화면 설계](/project-map-design.md) - 지속 프로젝트 지도에서 사람이 읽는 화면의 기준. 읽는 화면과 근거 기록의 분리, 문장형 제목·시각 근거의 슬라이드 구성, 글쓰기, 공용 템플릿(project-map 스킬)·글꼴·AI 기본값 회피, 데스크톱 최대화 화면 구조, 칸반 보드, 시각 자료, 고쳐 쓰는 갱신, 게시 전 점검.
