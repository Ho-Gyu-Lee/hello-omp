# 에셋의 AI 사용 권리와 검수·조립 원리

Godot TileMap/에디터·게임 판정/예측의 정본은 [Godot 에셋·에디터](/game/godot-assets-editor.md)에 유지합니다.

## 에셋의 AI 사용 권리

- 게임에 넣을 권리와 AI 참조 입력·학습(LoRA 포함)·생성물 판매·도구/모델 배포 권리는 분리해 실제 취득 채널과 적용 라이선스로 확인합니다.
- Unity Asset Store로 취득한 에셋은 [AS Terms 3.8(v)·EULA 2.2.1.1(g)](https://unity.com/legal/as-terms)(본문 개정 2024-12-04, 확인 2026-10-15)가 `Provider and/or Unity`의 명시적 동의 없는 AI/ML 학습·데이터셋·모델 입력 사용을 제한합니다. 로컬 추론이나 API 제공자의 학습 미사용 약속을 동의의 대체물로 보지 않습니다.
- 다른 판매 채널의 수정 허가나 제작 당시 `No AI` 표시만으로 AI 사용·재배포 허가를 추정하지 않습니다. 약관 조사는 에이전트의 업로드·학습·유료 호출에 대한 사용자 승인이 아닙니다.

## 검수·조립 원리

- **측정은 실제 결함을 검출해야 합니다.** 반입 검수는 대표 원본·개별 frame 단위로 하고, 목록 문서의 수량·범위·크기 주장은 원본을 다시 세는 검사로 대조하되 일부러 틀린 사본에서 그 검사가 실패하는지 확인합니다. 예: 인물은 frame의 일부만 차지하므로 frame 전체 평균 차이는 동작 복제 결함을 통과시키며, 80px 안팎 썸네일의 내용 라벨은 확대 확인 없이 믿지 않습니다.
- **조립은 구성요소가 아니라 최종 결과로 확인합니다.** 타일 번호·이름·source hash로 조립을 추정하지 않고 같은 배율의 원본 패치 → 실제 엔진 창의 발·그림자·가림·이음새 순으로 대조합니다. 예: 문틀·창처럼 투명한 개구부는 하부 재질까지 엔진 화면에서 확인하고 기존 충돌·높이·원본 픽셀을 보존합니다.
- **선택 알고리즘은 후보 집합의 한계를 넘지 못합니다.** 생성 건물은 크기·문 방향 조건마다 들어맞는 디자인 수를 먼저 셉니다. 후보가 하나뿐이면 hash 선택도 같은 건물을 나란히 반복하므로 후보를 늘리고 원본 1× 미리보기로 확인하며, 반입으로 atlas가 커지면 텍스처 메모리를 모바일 예산과 함께 보고합니다.
- **측정량이 사용자 판단 대상을 대표하는지 확인합니다.** 화풍 대조는 같은 화면에 서는 구매 에셋을 기준 집합으로 원본 배율에서 비교하고, 기준 범위를 벗어난 지표는 후보일 뿐이라 실제 게임 캡처로 확인하며 최종 미감 판단은 사용자가 합니다. 예: 바닥 위 색 드러남은 명도 비율인 HSV 채도가 아니라 chroma `(max−min)/255`로 봅니다.
- **원본의 표현력 한계를 색 보정으로 숨기지 않습니다.** tint는 RGB를 곱하므로 부위 합성 캐릭터의 미세 질감은 각 부위 안쪽 무늬·솔기·음영이 정합니다. 구매 캐릭터와의 격차가 부위 선택으로 닫히지 않으면 색을 조정하지 말고 다른 제작 경로(손 픽셀 작업·외주·디테일 오버레이 층)를 비용과 함께 사용자에게 올립니다.
