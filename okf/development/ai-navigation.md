# 상태 기계·탐색의 수명과 작업 예산

서버 권위·공개 집합 검사·서버 내부 AI 예외는 [서버 권위](/security/game.md)를 따릅니다.

## 원리

- **비동기 결과는 해당 작업 세대까지 검사합니다.** 상태 한정 타이머·완료·경로 요청 결과는 진입 세대 또는 행동 instance, 목표 세대·map 버전에 묶어 적용 시 확인합니다. 예: `Alive → Dead → Alive` 뒤 도착한 첫 Alive의 timeout은 같은 상태 이름이어도 새 행동의 이벤트가 아닙니다.
- **반복 갱신은 기존 진행을 되감지 않습니다.** 목적지를 주기적으로 다시 보내는 자동 이동에서 새 경로가 항상 현재 칸 중심으로 먼저 돌아가면 `속도 × 재계획 주기`가 중심까지 거리보다 짧을 때 같은 자리를 왕복합니다. 다음 지점으로 바로 가는 구간이 충돌 검사로 안전할 때만 시작 칸 중심을 건너뛰고, 속도를 낮춘 뒤 드러나므로 반복 재계획 회귀를 둡니다. 시간 제한을 늘려 증상을 숨기지 않습니다.
- **해법의 실패는 문제의 불가능성이 아닙니다.** 탐욕적 배치의 각도·순서 변형이 반복 실패해도 전체 제약의 불가능성 증거가 아닙니다. 사용자 조건과 구현자가 추가한 여유를 구분해 사용자 조건은 임의로 완화하지 않고 불필요한 여유부터 제거하며, 좁은 후보군은 유한 후보를 전체 조합으로 검토한 뒤 확정합니다. 요구끼리 충돌하면(예: 카메라 가시성과 맵 밖 비노출) 한쪽을 임의로 줄이지 않고 충돌을 드러내 우선순위를 사용자 요구로 정합니다. 예: "화면 위쪽" 같은 조건은 범위 이름이 아니라 투영식의 부호 조건으로 생성기·검증기·회귀에 각각 명시합니다.

## 부분 경로와 예산 고갈

- 도달 불가 목표는 연결 공간 대부분을 탐색할 수 있으므로 tick별 확장량·취소를 정하고 `complete`·`partial`·`no-path`·`budget-exhausted`를 구분합니다. 부분 경로 끝에 도착했다는 사실을 원래 목표 완료로 처리하지 않으며, 라이브러리의 부분 결과·고갈 플래그가 함께 올 수 있는지도 확인합니다([Detour query](https://recastnav.com/classdtNavMeshQuery.html), 확인 2026-10-15).
