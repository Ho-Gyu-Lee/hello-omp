# 상태 기계·탐색과 이동 모델

UI·워크플로·시뮬레이션·게임에서 필요한 가장 작은 상태·규칙·탐색 모델을 선택합니다. 모든 프로그램에 계층 FSM·학습 모델·새 AI 엔진을 요구하지 않습니다. 본문의 전술·전투·스폰·게임 트리는 해당 기능을 선택한 경우의 적용 조건입니다. 게임에 적용할 때는 [서버 권위](/security/game.md)와 지정 대상의 공개 집합 검사·서버 내부 AI 예외를 유지하며, 클라이언트의 경로·회피 결과를 합법 이동·명중 증명으로 쓰지 않습니다.

## 상태와 이벤트 수명

- 전이 요청과 확정을 분리한다면 현재 핸들러의 수명을 깨뜨리지 않는 경계에서 `old Exit → 상태 변경 → new Enter`를 처리합니다. 여러 요청의 우선순위·대체/큐잉·자기 전이를 정하고 Enter/Exit가 다시 전이를 요청하는 연쇄의 종료를 보장합니다. 실행 중 소유 객체의 파괴는 [루프 실행 경계](/development/execution.md)를 따릅니다.
- 공통 취소·정리가 반복되어 계층 FSM을 선택했다면 이벤트 소비/상위 전달, 초기 자식, 자식→부모 Exit·부모→자식 Enter, 상위 상태를 유지하는 내부 전이와 재진입을 구분합니다. C++ 클래스 상속만으로 이 런타임 의미가 생기지는 않습니다. 공유 상태 정의와 개체별 현재/예약 상태·타이머·대상은 분리하고 자기 참조 상태 객체의 복사·이동·풀 재배치도 확인합니다([SCXML 전이 의미](https://www.w3.org/TR/2015/REC-scxml-20150901/#SelectingTransitions)).
- 엔티티 generation과 상태 실행 세대는 별개입니다. 상태 한정 타이머/완료는 진입 세대 또는 행동 instance에 묶어 적용 시 확인합니다. `Alive → Dead → Alive` 뒤 도착한 첫 Alive의 timeout은 같은 상태 이름이어도 새 행동의 이벤트가 아닙니다. 전역 이벤트는 별도 유효 범위를 두고 취소·연결 해제·실행 시 검사를 수명 계약에 맞춰 선택합니다([SceneTreeTimer](https://docs.godotengine.org/en/4.7/classes/class_scenetreetimer.html)는 gameplay 상태를 자동 검증하지 않습니다).
- 순간 이벤트, 현재 조건, reset까지 기억하는 latch를 구분합니다. 이벤트 기억/해제 같은 필수 갱신을 순수 AND/OR 평가와 분리해 단락 평가로 잃지 않게 합니다. '동시 만족'과 '과거에 한 번씩 발생'은 다르며 발동/재무장·소유 수명을 정합니다. 기존 [접촉 전환 요청](/game/network-time-movement.md#접촉-트리거-기반-전환-요청)을 덮어쓰지 않습니다.
- 현재 상태만으로 원인을 찾기 어려우면 개체/generation·논리 tick·원인 이벤트·old/new state·수락/폐기 이유의 최근 이력을 제한된 ring에 남깁니다. 무제한 상시 로깅이 아니라 [필요한 진단](/development/runtime-diagnostics.md)의 선택입니다.

## A* 정확성과 상태 모델

다음은 유한 그래프·비음수 edge 비용·검색 중 고정된 이동/비용 모델에서 최소 `f=g+h`를 선택하는 표준 graph-search A*의 충분조건입니다. 다른 변형의 필요조건이나 모든 엔진의 최적성 보장으로 일반화하지 않습니다.

- 최저 비용 보장이 필요하면 `0 ≤ h(n) ≤ 실제 최소 잔여 비용`, 허용 목표에서 `h=0`을 유지합니다. g와 h의 단위를 맞추고 직선 거리×최소 이동 비용은 실제 edge가 그 하한을 지킬 때만 사용합니다. 낮은 비용 지형·portal/teleport·특수 이동을 넣으면 하한을 다시 검토합니다.
- 모든 edge에서 `h(u) ≤ cost(u,v)+h(v)`인 일관적 휴리스틱이면 최소 f로 꺼낸 노드의 g가 확정되어 closed 재개방을 생략할 수 있습니다. 허용적이지만 비일관적인 h에는 그 보장이 없습니다. 더 작은 g를 찾으면 부모·g·우선순위를 갱신하고 closed도 다시 확장 가능하게 합니다. 목표는 처음 발견했을 때가 아니라 유효한 최신 기록을 최소 f로 꺼냈을 때 성공입니다. 중복 heap 항목을 쓰면 낡은 항목 폐기 뒤 목표를 판정합니다([Boost A*](https://original.boost.org/doc/libs/1_89_0/libs/graph/doc/astar_search.html), [일관성·가지치기](https://www.cs.ubc.ca/~poole/aibook/2e/html2e/ArtInt2e.Ch3.S7.SS2.html)).
- 미래의 합법 전이와 비용이 같을 때만 같은 검색 상태로 합칩니다. 차량 heading·속도·회전 반경, 이동 능력, 문 상태, 진입 portal, 연속 노출 이력이 미래 비용을 바꾼다면 위치 하나의 g/visited만으로 합치지 않습니다. 방향별 비용도 비대칭일 수 있습니다. 모든 보행 agent의 차원을 늘리라는 뜻은 아닙니다.
- 과대평가 h·corridor 제한·장애물 근사는 품질·도달성을 바꿀 수 있습니다. 정확성을 보존하는 최적화와 근사 검색을 구분해 경로 비용·성공률·확장 수·지연을 함께 봅니다. 작은 그래프에서 Dijkstra와 대조하고 목표 최초 발견/최소 pop 차이, 재개방 필요, 0비용 순환, portal·일방 edge를 포함합니다.

## 이동 공간·회피·복구

- 격자/waypoint/영역/portal/navmesh의 노드 수뿐 아니라 구축 시간·메모리·질의 비용·실제 경로 품질을 비교합니다. 영역 내부 직선 이동과 portal 통과 가능성을 유지하고 긴 polygon·대표점의 우회를 확인합니다. 그래프 최저 비용이 연속 공간의 최단 경로와 같지는 않습니다. 변경 중 검색은 snapshot/버전을 고정하거나 변경을 지원하는 알고리즘의 계약을 따릅니다.
- 경로 데이터에는 중심점뿐 아니라 agent 반경·높이·단차·경사·필요 회전 공간을 반영합니다. 크기별 그래프·clearance 값·형상 검사 중 필요한 방식을 선택합니다. 보수적 침식이 안전을 높이면서 실제 가능한 좁은 통로를 누락할 수 있다는 완전성 경계도 남깁니다. Godot avoidance 반경과 bake의 `agent_radius`는 다른 계약입니다([NavigationMesh](https://docs.godotengine.org/en/4.7/classes/class_navigationmesh.html), [Recast rcConfig](https://recastnav.com/structrcConfig.html)).
- 전역 경로, 로컬 조타/회피, 실제 물리 충돌, 공격 시선은 다른 판정입니다. waypoint 생략·funnel·곡선 평활화는 agent 형상과 현재 장애물에서 구간 전체의 통행 조건을 유지해야 합니다. 로컬 회피는 대칭 대면·좁은 통로·막다른 곳의 도달 보장이 아닙니다([Godot NavigationAgents](https://docs.godotengine.org/en/4.7/tutorials/navigation/navigation_using_navigationagents.html)).
- 계획 공간 밖 위치의 최근접 투영점은 벽 반대편·위층일 수 있습니다. 같은 층/연결 성분에서의 안전한 연결을 확인하고 last-valid도 현재 조건으로 재검증합니다. 복구가 불가능하면 명시적 실패/정지 또는 승인된 teleport/respawn으로 처리합니다. stuck 해소를 이유로 충돌·서버 검증을 끄지 않습니다.

## 작업 예산과 사전계산

- 도달 불가 목표는 연결 공간 대부분을 탐색할 수 있습니다. 요청 큐·tick별 확장량·scratch/출력 용량과 취소를 정하고 `complete`·`partial`·`no-path`·`budget-exhausted`를 구분합니다. 경로가 비어 있지 않거나 부분 경로 끝에 도착했다는 사실을 원래 목표 완료로 처리하지 않습니다. 라이브러리의 부분 결과·고갈 플래그가 함께 올 수 있는지도 확인합니다([Detour query](https://recastnav.com/classdtNavMeshQuery.html)).
- 읽기 맵과 요청별 g/부모/open/closed·scratch를 구분합니다. mutable query를 동시 요청이나 진행 중 분할 검색이 덮어쓰지 않게 하며 목표 세대·map 버전을 완료 적용 시에도 확인합니다. 리더 경로 공유는 각 유닛의 크기·능력·시작점 연결을 만족할 때의 선택입니다. 일반 공정성은 [서버 큐 기준](/development/server-checklist.md#큐입장처리-예산)을 따릅니다.
- 반복 질의에 연결 성분·계층 그래프·clearance·시선 표가 유리한지 생성/저장/무효화 비용까지 비교합니다. 양방향 연결 라벨을 일방 edge의 도달성에 그대로 쓰지 않습니다. O(N²) 쌍별 표와 섹터 근사의 오차를 구분하고 문·파괴 지형·높이·자세·agent 조건의 변경을 반영합니다. 위험 근사의 보수성은 권위 명중이나 비공개 정보 인가의 정확성 보장이 아닙니다.

## 전술·퍼지·학습·게임 트리

- 전술 경로가 실제 요구일 때 이동 시간/거리와 비음수 위험 비용을 같은 목적함수로 정의합니다. 긴 edge의 양 끝 평균만으로 중간 노출을 놓치지 않습니다. 록온처럼 연속 노출이 결과를 바꾸면 총 노출 합만으로 충분하지 않습니다. 노드의 mutable `aiming` 하나를 덮어쓰는 대신 필요한 이력을 검색 상태로 보존하거나 근사임을 명시합니다. 적 위치 snapshot·잠재 이동 근사는 미래 위치의 사실이 아닙니다.
- 퍼지 소속도는 확률이 아니며 범주 합이 1일 필요가 없습니다. 입력 단위·유효 영역·규칙 덮임·활성 규칙 없음·동률의 결과를 정합니다. centroid와 최대값 계열은 출력 의미와 비용이 다릅니다. 연속 점수의 argmax는 경계에서 이산 행동이 튈 수 있으므로 행동 유지가 필요하면 별도 히스테리시스를 정합니다([MathWorks foundations](https://www.mathworks.com/help/fuzzy/foundations-of-fuzzy-logic.html), [defuzzification](https://www.mathworks.com/help/fuzzy/defuzzification-methods.html)).
- 시연/사례 기반 학습을 선택하면 관측과 행동을 같은 계약으로 기록하고 학습·평가·실행의 전처리·단위·bin을 맞춥니다. 양자화로 합쳐진 상황은 구분할 수 없으며 센서별로 본 조건의 조합이 실제 시연됐다는 보장도 없습니다. 미관측·충돌 조합과 독립 평가를 확인합니다. 선택 계층의 허용 행동 제한과 실행 계층의 합법 전이 검사는 별개입니다. 사람·휴리스틱·학습 정책으로 바꿔도 실행 경계 검증은 유지합니다([전처리·평가 분리](https://scikit-learn.org/stable/common_pitfalls.html)).
- 적대적 탐색은 번갈아 두는 제로섬 minimax/negamax 가정이 실제 규칙에 맞을 때 씁니다. 깊이 제한 평가의 수평선 효과와 예산 중단을 구분하고 반복 심화의 마지막 완결 깊이 결과를 보존합니다. alpha-beta 순서·quiescence·전이표는 모델에 맞을 때 선택하며 체스 전용 상수를 일반 AI에 복사하지 않습니다([Stockfish 검색 사례](https://raw.githubusercontent.com/official-stockfish/Stockfish/master/src/search.cpp)).

- 상태 재진입 세대·자기 참조 복사/이동·경로 이력의 상태 확장은 책의 원리와 현대 계약에서 도출한 기준입니다. Gems3의 단일 `aiming` 예제에 A* 최적성을 자동 부여하지 않으며, collision을 무시하는 복구 예제를 권위 이동 정책으로 채택하지 않습니다. 현대 문서 대조: 2026-10-15.
- 위 검증 조건은 제품 구현에서 수행할 항목입니다. 이번 문서 조사에서 게임 AI/내비게이션 제품을 구현하거나 성능을 실행 검증한 것은 아닙니다.

## 제약 배치 탐색의 사례
- **배치 탐색 실패와 요구 완화:** 탐욕적 배치의 각도·순서 변형이 반복 실패해도 전체 제약의 불가능성 증거는 아닙니다. 사용자 조건과 구현자가 추가한 여유(예: 벽 사이 빈 칸)를 구분하고, 실제 비중첩·문 앞 통행을 유지한 채 불필요한 여유부터 제거합니다. 좁은 핵심 건물군은 문 양옆을 포함한 유한 후보를 전체 조합으로 검토한 뒤 확정합니다. 화면 위쪽 같은 조건은 범위 이름만으로 보장되지 않으므로 투영식의 부호 조건으로 생성기·검증기·회귀에 각각 명시합니다.

## 주기적 재계획과 이동
- **저속의 주기적 경로 재계획:** 목적지를 일정 주기로 다시 보내는 자동 이동(추적·자동 사냥)에서 새 경로가 항상 현재 칸의 중심으로 먼저 돌아가면, `속도 × 재계획 주기`가 중심까지 거리보다 짧을 때 같은 자리를 왕복합니다. 속도를 낮추는 변경 뒤에 드러나므로 반복 재계획 회귀를 둡니다. 다음 지점으로 바로 가는 구간이 충돌 검사(`CanTraverse` 등)로 안전할 때만 시작 칸 중심을 건너뛰고, 막힌 모서리 옆의 음성 사례(중심 유지·매 tick 점유 가능·정확한 도착)를 함께 고정합니다. 권위와 예측이 같은 함수를 쓰는지 확인하고 시간 제한을 늘려 증상을 숨기지 않습니다.
