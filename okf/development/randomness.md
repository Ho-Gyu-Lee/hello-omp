# 난수·절차 생성·재현 계약

앱·시뮬레이션·테스트·게임에서 재현이나 무작위 선택을 사용하는 경우의 계약입니다. 본문의 전투/보상·음성/파티클은 업무 결과와 선택적 표시 스트림의 예시이며, 방·스폰은 제약 생성의 사례입니다. 모든 프로그램에 게임 시뮬레이션을 요구하지 않습니다. 게임 락스텝·비공개 정보·권위·출하 치트 훅은 [게임 재생](/game/random-replay.md)에 별도로 둡니다.

## 난수 계약

- 전투·보상 판정의 난수와 음성·파티클·카메라 같은 표시 전용 난수를 분리합니다. 오디오 비활성화나 워커 실행 순서 때문에 판정 스트림의 소비 횟수가 바뀌지 않게 합니다. 이미 [동기화 검증](/game/network-sync.md)에서 요구하는 용도별 스트림에 더해, 실제 소비 지점·시드/현재 상태·초기 조건을 재생 입력에 포함합니다.
- 플랫폼·업데이트를 넘는 재현이 필요하면 PRNG 알고리즘, 원시 출력→범위/분포 매핑, seed 파생, 콘텐츠/생성 버전을 함께 고정하고 호환을 검사합니다. 표준 C++ 난수 엔진의 수열 규정과 구현 정의인 분포 알고리즘은 다릅니다. 같은 seed의 `uniform_*_distribution`·`shuffle`이 모든 라이브러리에서 같은 결과라는 가정을 두지 않습니다([C++ distributions](https://eel.is/c++draft/rand.dist.general)). Godot RNG도 내부 알고리즘을 구현 세부로 명시합니다([RandomNumberGenerator](https://docs.godotengine.org/en/4.7/classes/class_randomnumbergenerator.html)).
- 좌표·객체 ID를 그대로 seed로 반복 투입해 비슷한 공간 패턴을 만들지 않는지 확인합니다. 안정 ID별 파생 스트림은 방문/작업 순서 의존을 줄이는 선택이지 통계적 독립성의 자동 증거가 아닙니다. 책의 LCG·단순 좌표 결합을 새 표준으로 만들지 않습니다. 재현용 PRNG를 토큰·비밀 생성용 CSPRNG와 혼동하지 않습니다.
- 균일한 원시 출력도 범위 크기가 N의 배수가 아니면 `% N`으로 편향될 수 있습니다. 마스크/거절 방식은 사용하는 비트의 품질·범위 전제를 확인합니다. 평균 시도 수가 작다는 것이 호출별 고정 상한은 아닙니다. 기존 검증된 분포를 우선하고 재현이 필요한 경우 범위 매핑까지 고정합니다([bounded random](https://pcg-random.org/posts/bounded-rands.html); *Game Programming Gems 3* 한국어판 PDF p.229–230).
- 무작위 음악/대사에서 한 순회 내 반복을 막는 비복원 선택과 매번 독립 확률 추출은 다른 계약입니다. 셔플백을 선택하면 후보 변경·순회 종료/재시작을 정의합니다. 반복을 줄이려는 외형 요구로 보상 확률을 조용히 바꾸지 않습니다. 소수 stride의 비반복 방문은 모든 순열의 균등 샘플링을 뜻하지 않습니다([C++ shuffle](https://eel.is/c++draft/alg.random.shuffle)).

## 생성 수락과 종료

- 같은 seed로 같은 잘못된 맵을 만드는 것도 재현입니다. 방/문 그래프의 필요한 도달성, 허용 스폰·자원 배치, 경계·청크 접합을 별도로 검사합니다. 제약으로 허용 후보가 공집합이 됐을 때 무한 재추첨하지 않고 고갈·실패를 반환합니다. 반복 상한 뒤 제약을 몰래 완화하지 않습니다.
- 격자 세분화처럼 이전 단계의 이웃 값에 의존하는 생성은 계산 단계와 경계 조건을 보존합니다. 평행화·청크 방문 순서를 바꿀 때 경계 샘플의 공유·일관성과 생성 결과를 비교합니다. 지형 형상·실제 통행은 [수치·공간](/development/numerics-spatial.md) 및 [AI·길찾기](/development/ai-navigation.md)와 함께 확인합니다.

## 기록과 검증
- 게임 규칙 재현에는 고수준 명령, 초기 월드/콘텐츠, 논리 tick, 난수 상태를 기록하는 방식을 검토합니다. 이 경로는 UI 배치 변화에 덜 민감하지만 실제 OS 입력·포커스·표시 검증을 대신하지 않습니다. 폴링 입력이나 직접 상태 변경이 기록 경로를 우회하지 않는지도 확인합니다. 입력 기록만으로 게임 상태 결정성이 생기지는 않습니다([Unity InputEventTrace](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.11/api/UnityEngine.InputSystem.LowLevel.InputEventTrace.html)).

## 근거와 적용 범위
- *Game Coding Complete* 1판 한국어 제공본 PDF p.135–148, 614–624: 공용 RNG를 음성 스레드가 소비해 재생이 어긋난 사례, 비복원 순회, 게임 이벤트 재생·테스트 훅. *Game Programming Gems* 한국어판 PDF p.199–207, 623–648: 예측 가능한 난수·절차 생성·도달성/재추첨 실패.

게임 개발 서적의 원리에서 도출했지만 난수·생성·재현의 전제는 해당 기능을 사용하는 앱/서비스에도 같습니다. 인용한 엔진/표준 라이브러리의 실제 계약과 성능/이식성 한계는 유지하며, 알고리즘 구현·실제 제품의 재현 성공을 이 분류 작업에서 새로 검증했다는 뜻은 아닙니다.

## 검증 시계와 라이브 상태
- **표시 검사와 라이브 시계 분리:** 애니메이션 검증에서 주입한 미래 표시 시각을 실제 세션의 단조 렌더 시계로 그대로 되돌리지 않습니다. 라이브 경로를 재개할 검사는 새 장면으로 분리하거나 원래 시계를 변경하지 않는 관찰을 사용합니다. 에러 로그가 있는데 실패한 단언이 0개라는 이유로 성공 처리하지 않습니다.
