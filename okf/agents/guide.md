# 에이전트 가이드

현재 역할별 모델·추론 강도·fallback의 정본은 `config/settings.conf`다. 이 문서는 그 배정의 이유와 omp의 비자명 계약만 둔다.

## 번들 에이전트와 모델 역할
OMP 18.20.0 `omp agents unpack --dir <격리 경로> --json`·`omp://models.md`·`omp://settings.md`, 확인: 2026-11-13. 확인 목적으로 기본 에이전트 디렉터리에 풀어 번들 override를 만들지 않는다.
- 번들은 `scout`·`reviewer`·`security-reviewer`·`task`·`sonic`·`seance` 6종이다. `scout`·`sonic`은 `@smol`(medium), `task`는 `@task`(auto), `reviewer`는 `@slow`로 해석되고, 번들 model 지정이 없는 `security-reviewer`와 이 설정의 사용자 정의 `design-reviewer`(구현 전 설계 검토 전용, `agents/design-reviewer.md`)는 `task.agentModelOverrides`로 `@slow`를 명시한다. 값에 명시한 `:level` suffix가 번들 기본 추론 강도보다 우선한다. 에이전트별 모델은 파일 복사 대신 이 override로, thinking level은 `modelRoles` suffix로 바꾼다.
- `modelRoles`는 용도별 모델 배정이지 에이전트 등록이 아니다. 역할 이름은 `agent`에 넣을 수 없고(`Unknown agent`로 거부) `librarian`·`designer`는 번들이 아니다. `designer`는 이 프로필의 사용자 정의 chat 별칭이라 `@designer`를 고르거나 참조하는 커스텀 에이전트가 있어야 쓰인다. 미배정 `tiny`는 `@smol`, 미배정 `memory`는 `@tiny`, 미배정 `widget`(OMP 18.15.0~, 15초 넘게 도는 백그라운드 작업의 위젯·한 줄 설명 작성)은 `smol`처럼 해석되고(`omp://settings.md`), model-kind 역할(`image`·`web`·`speech`·`dictation`·`judge`)에 일반 chat 모델을 무조건 배정하지 않는다. `vision`은 `read <이미지>?q=...` 같은 이미지 질의에 쓰이고 이미지 입력을 지원하는 메인 모델이 이미지를 직접 읽는 경로는 바꾸지 않는다(`omp://models.md`). `advisor`는 역할 배정과 별도로 `advisor.enabled`(OMP 기본 off)로 켜며 노트 출력 지침의 정본은 `rules/WATCHDOG.md`다.
- `generate_image`는 `generate_image.enabled=true`(기본 false)이고 명시적 도구 목록이 있으면 거기에 포함될 때만 등록된다. `openai-codex` 구독 경로는 백엔드가 이미지 모델을 고르므로 OMP에서 지정할 수 없다(`omp://tools/generate_image.md`, [#11322](https://github.com/can1357/oh-my-pi/issues/11322)). GPT Image 2.5·2.6을 명시적으로 지정하는 확인된 경로는 OpenAI API 키이며, OMP 18.20.0 번들 카탈로그의 `openai`에는 두 세대의 행이 없어(2.5 행을 넣는 PR #14373 미병합, 확인 2026-11-13) `models.yml`의 `providers.openai.models`에 `api: openai-images` 행을 둔다. 기본 `auth: apiKey`에서 내장 provider에 custom 행을 두면서 provider 수준 `baseUrl`·`apiKey`를 빠뜨리면 검증 실패로 `models.yml`의 custom 설정 전체가 꺼진다(18.12.6 실측, 18.20.0 `omp://models.md`의 검증 규칙도 같다). 유료·로컬 경로 선택은 [AI 에셋 생성](/development/ai-asset-generation.md#유료로컬-경로-선택)을 따른다.
- 에이전트 정의의 `tools`를 생략하거나 YAML null로 두면 기본 내장 도구 전체가, 도구 이름이 없는 선언(`[]`·빈 CSV·잘못된 값)은 내장 도구 없음이 선택된다. 어느 쪽이든 MCP·extension·custom 도구는 additive라 `tools`는 격리 수단이 아니다(`omp://task-agent-discovery.md`). task 자식의 `lsp`는 `task.enableLsp`(기본 false)가 켜져 있을 때만 생기며, 켜면 일반 task 자식은 도구 제한 세션이 아니어서 `rename`·code action 같은 변경 동작도 열린다(OMP 18.20.0 `sdk.ts`의 `lspReadOnly` 기본값이 `restrictToolNames`, 확인 2026-11-13). 읽기 전용으로 둘 검토자의 `tools`에는 `lsp`를 넣지 않는다.

## 현재 배정의 이유
- 메인·계획과 구현 `task`는 모두 Opus 5.5다(구현을 Sonnet 5.5 xhigh에서 Opus 5.5 high로 바꾼 사용자 결정, 2026-11-02). 독립 평가에서 Sonnet 5.5 xhigh는 Opus 5.5 high보다 점수가 낮고 비용이 높았고(AA Intelligence Index v4.3: 52점·$2.74 대 54점·$1.82, v5.0.1에서도 50점·$4.09 대 52점·$3.46로 같은 방향, [AA](https://artificialanalysis.ai/models/claude-opus-5-5-high) 조회 2026-11-13), Anthropic도 코드 작성은 Opus에 두고 조회·검색용 서브에이전트만 낮추라고 권한다([What a task costs on Opus 5.5](https://claude.dev/blog/what-a-task-costs-on-opus-5-5), 2026-09-25). 메인과 구현이 같은 Anthropic 한도·인증에 의존하므로 소모량은 사용량 기록으로 확인한다.
- 정밀 검토 `slow`·화면 분석 `vision`·감시 `advisor`·탐색·커밋은 OpenAI 계열이라 기본 경로에서 메인·구현과 교차 검토가 된다. 교차 검토의 효과는 평균 정확도 상승보다 서로 다른 놓침을 잡는 데 있고([arXiv 2610.01471](https://arxiv.org/abs/2610.01471)), Astra 리뷰는 재현율이 높은 대신 정상 변경에도 지적을 많이 낸다(168 PR·high effort에서 정상 PR 변경 요구 Astra 47.8%·Opus 5.5 20.7%, [TLE Labs](https://cross-review.tlelabs.com/benchmark/) 2026-10-26). fallback은 반대 provider를 두어 한도·장애에 대응하며 품질에 따른 자동 상향이 아니다. 한도·장애로 작성 모델과 검토 모델이 같은 provider가 되어도 역할표는 이를 자동 분기하지 않는다. Anthropic 쪽이 막혀 작성 모델이 OpenAI가 되면 같은 OpenAI reviewer만으로는 충족하지 않으므로 실제 실행 모델을 확인하고 아래 「교차 모델 독립 검토」를 따른다. 반대로 Codex 한도 소진으로 `slow`가 fallback인 Opus로 돌았으면 그 검토도 교차 모델 검토가 아니다.
- 추론 강도는 난도별이다. 메인·계획·정밀 검토는 xhigh, 구현·디자인·화면 분석·advisor는 high, 탐색·커밋은 medium, 제목·메모리·`widget`은 low다. 자동 난도 판정과 일괄 xhigh·max 강제는 도입하지 않는다. 공식 시작점은 Opus 5.5 medium(30분 넘는 에이전트 작업은 xhigh), Sonnet 5.5 medium에서 high, Codex의 Astra low·Luna high이고 xhigh·max는 평가로 이득이 확인될 때만 쓰라고 한다([effort](https://platform.claude.com/docs/en/build-with-claude/effort), [Codex models](https://learn.chatgpt.com/docs/models), 확인 2026-11-13). max는 과잉 사고와 128K 출력 상한 도달 보고가 반복된다. 이 배정은 운영 판단이지 로컬 품질·비용 A/B 결과가 아니며 외부 평가도 로컬 품질 비교가 아니다([정확성](/accuracy.md)).
- Fable 5.2는 기본 역할·fallback에 넣지 않고, 메인 세션이 고른 하위 작업만 task의 `model: "anthropic/claude-fable-5-2:xhigh"`로 맡긴다. 5.1에서 5.2로 바꾼 근거는 플랜 취급이 5.1과 같고(같은 플랜 안내) API 단가가 입력·출력 $8·$40로 5.1의 $10·$50보다 낮으며 API 사용면이 5.1과 같다는 점이다([Fable 5.2](https://platform.claude.com/docs/en/models/fable-5-2/overview), [마이그레이션 가이드](https://platform.claude.com/docs/en/models/fable-5-2/migration-guide), 조회 2026-11-10). OMP 18.18.6의 `anthropic` 구독 경로에서 실호출이 성공했다(2026-11-10). 주간 Fable 할당량이 쓰이지 않은 채 초기화되지 않도록 추론 품질이 결과를 좌우하는 작업에는 묻지 않고 맡기고, 한도 근처에서만 승인을 받는다(사용자 결정 2026-11-03, 기준 문장의 정본은 `rules/RULES.md`). 승인 문턱을 `omp usage`의 `Claude 7 Day`·`Claude 7 Day (Fable)` 중 하나가 80% 이상일 때로 둔 이유는 두 가지다. Fable은 별도 한도가 아니라 플랜의 일반 주간 한도에서 다른 모델보다 빠르게 차감되어 메인·구현의 Opus와 같은 한도를 나눠 쓰고, Max·Ultra·Team premium 좌석의 Fable 상한(주간 한도의 50%)에 닿은 뒤 계속 쓰려면 usage credits(추가 과금)가 필요하다. Pro·Team standard 좌석에서는 첫 사용부터 usage credits로만 쓰여 구독 밖 과금이다([플랜 안내](https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan), 확인 2026-11-13). Fable 5.2 출시 혜택으로 받은 Fable 한도 reset(Fable 포함 플랜은 가입 기간에 따라 1~3개, 2027-03-08 만료, Fable 주간 사용분과 5시간 창을 되돌리며 상한 50%는 그대로, [출시 혜택](https://support.claude.com/en/articles/17506494-claude-fable-5-2-launch-offers))은 `omp usage`에 saved reset으로 보이고, OMP는 이를 `claudeResets.autoRedeemFable`로만 다뤄 기본 `unset`에서는 묻기 전에 쓰지 않으며 `omp -p`처럼 물을 UI가 없으면 쓰지 않는다(OMP 18.18.7~, 18.20.0 확인 2026-11-13). `omp usage`(`--json` 포함)의 Anthropic 보고에는 플랜·좌석 등급이 없어 `Claude 7 Day (Fable)` 칸이 보인다는 것만으로 포함 여부를 판정할 수 없으므로(OMP 18.20.0, 확인 2026-11-13), 좌석 등급이나 사용자 확인 없이 Fable 전환을 구독 안 사용으로 가정하지 않는다. 세션 전체는 `/switch anthropic/claude-fable-5-2:xhigh`(세션 전용)로 바꾸며, 메인은 세션의 작업 대부분이 위 기준에 들 때 이를 제안한다. TUI `/model`은 인수 없이 선택기를 열고 선택자는 `/switch`가 받는다(OMP 18.20.0 설치본 `src/slash-commands/builtin-modes.ts`, 확인: 2026-11-13).
- 메인을 Fable 5.2로 바꾸지 않는 이유는 성능은 앞서도 비용이 낮지 않아서다. Fable 5.2는 Anthropic 발표 표의 거의 모든 항목과 AA Intelligence Index v5.0.1(max 65 대 59)에서 Opus 5.5를 앞서지만, API 단가는 입력·출력 $8·$40로 Opus 5.5의 $4·$20의 두 배이고(캐시 읽기만 $0.20로 같다) AA 과제당 비용도 같은 추론 강도에서 더 높다(max $26.54 대 $10.04). Fable을 낮은 강도로 돌려 Opus 높은 강도와 비슷한 점수를 더 싸게 얻는 구간만 있다(FrontierCode 2.0에서 Fable high 45.3%·Opus max 45.5%, 과제당 비용 약 절반, Anthropic 자체 측정). 구독에서는 위 항목의 한도 조건 때문에 세션 대부분을 차지하는 메인에 두면 주간 한도의 절반을 넘는 사용을 Fable로 할 수 없고, 일반 주간 한도와 Fable 상한 중 먼저 닿는 쪽에서 usage credits나 다른 모델로 넘어가야 한다. Fable 5.2의 thinking block은 Fable·Mythos 5.2 밖의 모델이 읽지 못해 전환한 턴에서 추론 맥락이 사라진다. Anthropic은 Fable 5.2의 안전장치가 사이버보안 작업 대부분을 차단한다고 밝히며, 대부분의 코딩·지식 작업은 Opus 5.5에서 시작하고 xhigh·max에서도 부족할 때 Fable로 올리라고 권한다([발표](https://www.anthropic.com/claude-fable-and-mythos-5-2), [모델 선택](https://platform.claude.com/docs/en/about-claude/models/choosing-a-model), [가격](https://platform.claude.com/docs/en/about-claude/pricing), [AA](https://artificialanalysis.ai/models/releases/claude-fable-5-2), 조회 2026-11-11). Opus·Fable의 새 세대나 단가 변경이 나오면 이 비교를 다시 한다.
- Fable 5.2의 공식 시작점은 high이고 xhigh는 가장 어려운 장기 코딩·에이전트 작업용이다([effort](https://platform.claude.com/docs/en/build-with-claude/effort)). Fable에는 그런 작업만 맡기므로 xhigh를 유지한다. Anthropic은 Fable 5.2가 xhigh 이상에서 자기 작업을 검토하는 하위 에이전트를 띄우는 것을 관찰했고(5.1은 같은 작업에서 하지 않음, 마이그레이션 가이드), 이 설정의 `task.maxRecursionDepth`는 2라 Fable task 자식도 하위 task를 띄울 수 있다. Fable에 맡긴 작업의 사용량은 하위 실행까지 합쳐 본다. 프롬프트로 생각을 줄이라는 문장은 5.2에서 medium 이상일 때 듣지 않으므로 생각 깊이는 추론 강도로만 조절한다.
- 카탈로그의 `claude-mythos-5`·`claude-mythos-5-1`·`claude-mythos-5-2`는 Fable과 같은 모델의 안전장치를 완화한 검증 프로그램 승인 조직 전용판이라 구독 계정의 후보가 아니다([Mythos 5.2](https://platform.claude.com/docs/en/models/mythos-5-2/overview), 조회 2026-11-10). 카탈로그에 있다는 것은 접근 권한의 근거가 아니다.
- `image`는 구독 경로 `openai-codex/gpt-image-2`로 고정하고 fallback을 `[]`로 비우며 `generate_image.enabled=true`로 켠다(사용자 결정, 2026-10-26). 다른 인증이 생겨도 역할 기본 우선순위 목록의 다른 이미지 모델(API 과금 경로일 수 있음)로 자동 전환되지 않게 하려는 것이다. `[]`는 활성 모델 자신의 이미지 후보와 요청의 `model` 인자를 막지 않으므로(OMP 18.20.0 `omp://tools/generate_image.md`, 확인 2026-11-13) API 키 OpenAI 모델로 세션을 돌리면 Codex 후보가 HTTP 오류(한도 소진 포함)로 실패할 때 그 경로가 쓰일 수 있고, 다른 이미지 인증이 생기면 `model` 지정으로 그 모델이 직접 선택될 수 있다. 18.20.0의 `openai-codex` 이미지 카탈로그도 `gpt-image-2` 하나뿐이다. 경로 선택 방향은 [AI 에셋 생성](/development/ai-asset-generation.md#유료로컬-경로-선택)을 따른다.

## 설정 계약
- 설정 저장 위치는 활성 agent dir의 `config.yml`이다. `omp config set task.agentModelOverrides ...`는 dotted path이지만 YAML에는 `task: { agentModelOverrides: ... }`처럼 중첩해 쓴다.
- 제목 생성 기본값은 메인 모델 fork(OMP 18.8.0~)이고 `tiny` 배정만으로는 바뀌지 않는다. `TITLE_SYSTEM.md`가 발견되면 첫 제목부터 tiny 제목 모델이 짓고(`omp://config-usage.md`, OMP 18.20.0 확인 2026-11-13), 이 프로필은 그 파일이 발견되지 않는 경우에도 같게 하려고 `title.generator=tiny`를 함께 명시한다.
- `modelRoles`·`retry.fallbackChains`·`task.agentModelOverrides` 변경은 다음 서브 실행·fallback에 재로딩되지만 실행 중인 메인·이미 시작한 서브의 모델은 바꾸지 않는다. CLI/env/overlay/resume 모델은 별도 우선순위다(`omp://settings.md`, OMP 18.20.0 확인: 2026-11-13).
- `retry.usageReservePct` 기반 자동 전환은 신뢰 가능한 coding-plan usage report에서만 동작한다(일반 API key·unknown usage·후보 불가에서는 보장 안 됨). `providers.anthropic.serverSideFallback`은 Anthropic refusal fallback beta의 옵트인이며 OMP의 오류·429·quota fallback과 다르다. 카탈로그의 체인은 Fable·Mythos 요청을 `claude-opus-5`로 넘기도록 고정되어 있어 `claude-opus-5-5` 등 그 밖의 모델에는 대체 경로가 없다(`omp://settings.md`, OMP 18.20.0 확인 2026-11-13). 역할·fallback을 모두 쓰려면 두 provider의 유효 인증이 필요하다.
- Anthropic 모델의 cyber 거부는 모델이 지침 때문에 거부하는 것이 아니라 API 서버의 분류기가 응답 전에 내는 오류다(`stopReason: "error"`, 본문 `Refusal (cyber)`, `stopDetails.category: "cyber"`). 분류기는 사용자 메시지뿐 아니라 세션이 읽는 파일·도구 결과까지 보고, 시스템 프롬프트나 에이전트 지침으로 판정을 바꿀 수 없다. 사용자 프롬프트만 담은 제목 생성 요청도 같은 이유로 차단되므로 원인은 요청 내용이다(2026-11-10 실측, OMP 18.18.6, `anthropic/claude-opus-5-5` 구독 OAuth 경로). 요청에 "방어 목적"을 밝힌 문장이 있어도 차단된 사례가 있고, 분류기 회피를 노린 지침·문구 수정은 그 자체로 안전장치 우회 시도라 하지 않는다. 공식 경로는 Cyber Verification Program 승인(방어 등급이 사고 대응·취약점 분류와 검증·탐지 엔지니어링을 포함)과 오탐 피드백 신고이고, 승인 뒤에도 일부 오탐 거부가 남을 수 있다고 문서에 적혀 있다([CVP](https://support.claude.com/en/articles/14604842-cyber-verification-program), [refusals and fallback](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback), 조회 2026-11-10).
- 이 거부도 provider 오류로 취급되어 `retry.modelFallback`이 `retry.fallbackChains`의 다음 홉을 고른다. 복구 여부는 다음 홉이 실제로 쓸 수 있는 모델인지에 달린다. 2026-11-10 사례에서는 `default` 첫 홉 `openai-codex/gpt-6-astra`가 `usage_limit_reached`로 실패한 채 복구가 멈췄다. 승인 전 같은 성격의 작업을 이어 가려면 세션 모델을 다른 provider 모델로 바꾸는 것이 즉시 동작하는 유일한 수단이며, 다룰 자료의 보관 위치·제공자 정책을 먼저 확인한다.

## 게임·서버·디자인 사용 경로
사용자의 개발 방향은 [방향](/direction.md)을 따른다.
- 복잡한 클라이언트·서버 구조는 Opus 메인이 요구·불변조건·경계를 정리하고 `task`가 구현하며 작성 계열과 다른 reviewer가 검토한다. 수락 기준은 [서버](/game/server-checklist.md)·[클라이언트](/game/client-checklist.md) 체크리스트를 따른다.
- 게임 아트·UI·레벨은 Opus 메인 또는 `@designer` 모델이 방향·대안·추천안을 정하고 `task`가 구현하며 Astra `vision`이 실제 화면을 교차 분석한다. 일반 `task`에는 구현 목표·제약·검증 기준을 전달한다. 실제 시각 자료가 없으면 관찰한 것처럼 평가하지 않는다.

## 교차 모델 독립 검토
독립 검토가 필요한 산출물의 실제 작성 모델이 OpenAI인 경우(fallback 포함), 작업 산출물 디렉터리에 아래 일회성 YAML을 두고 별도 fresh session의 `reviewer` 또는 `security-reviewer`를 실행한다. `--config`는 그 프로세스에만 적용된다. 검토 범위·수락 기준·변경 파일·실행 근거를 프롬프트로 전달하고 구현자의 자기평가를 주입하지 않는다.

```yaml
# <작업 디렉터리>/anthropic-review.yml
task:
  agentModelOverrides:
    reviewer: "@plan"
    security-reviewer: "@plan"
```

```sh
omp --config <작업디렉터리>/anthropic-review.yml --model @plan -p "<대상과 근거를 지정하고 reviewer 독립 검토를 요청>"
```

- `@plan`은 이 프로필에서 Opus xhigh다. 모델 이름의 자기보고 대신 자식 session의 provider/model 기록을 확인하며, fallback으로 다시 OpenAI가 실행되면 교차 모델 검토가 아니다.
- task 호출의 `model`은 `task.perCallModel`(OMP 18.14.2~, 기본 `off`)이 `on`일 때만 받는다(`eval`이면 eval `agent()`·`workpool()`에서만). 도구 스키마에도 `on`이거나 번들 `seance`를 띄울 수 있을 때만 이 필드가 보이고(OMP 18.18.4~, 그 전에는 늘 보였다), 보이지 않을 때 보낸 값도 버려지지 않고 사전 검사에서 거부된다. 허용되는 모델은 운영자 설정(프로젝트 설정 제외)의 chat 역할에 배정된 모델, 선택한 에이전트 자신의 모델, 부모의 현재 모델뿐이고 `task.agentModelOverrides` 항목이 있는 에이전트에는 거부된다(`omp://tools/task.md`, `omp://task-agent-discovery.md`, OMP 18.20.0 확인 2026-11-13). 지정한 모델을 쓸 수 없으면 다른 모델로 넘어가지 않고 실패한다. 이 설정은 `on`이지만 `task.perCallModelAllow`로 Fable 하나만 열었으므로(사용자 정의 역할 `premium`이 허용 근거) 교차 모델 검토를 task 호출의 `model`로 대신하지 않는다. Fable 지정 기준과 승인 문턱은 설정의 승인 창이 아니라 지침(`rules/RULES.md`)이 정한다(사용자 결정 2026-11-02).
- 설정 없이 런타임에 서브에이전트 모델을 고르는 경로는 사용자가 메시지에 `^provider/model`을 태그하는 것이다. 태그한 모델마다 `m1`·`m2` 가명이 생기고, 이 가명을 task·eval `agent()`·`workpool()`의 `agent`로 쓰면 그 모델의 일반 task 템플릿으로 실행된다. `reviewer`·`security-reviewer` 같은 전용 템플릿은 쓰이지 않는다(OMP 18.15.0, `omp://task-agent-discovery.md`, `-p`에서도 실측 2026-11-02). 태그에 `^provider/model:high`처럼 추론 강도를 붙이면 그 강도로 시작하고(`task.maxEffort` 상한을 받지 않음) 모델·강도 쌍마다 가명이 따로 생기며, 강도를 붙인 가명에는 task의 `model`을 함께 줄 수 없다(OMP 18.17.0~, 같은 문서 18.20.0 확인 2026-11-13). 에이전트가 만든 프롬프트로는 태그를 등록할 수 없으므로 필요하면 사용자에게 태그를 요청한다.
- `/agents`나 `omp config set task.agentModelOverrides`는 전역 영속 변경이고 record 전체 교체로 기존 security reviewer 배정을 잃을 수 있으므로 일회성 검토에 쓰지 않는다.

## 구독과 인증의 경계
설정 파일은 구독 결제·플랜 확인·API 크레딧 수령·인증 전환을 하지 않으며, 일반 API key 크레딧 잔액은 `retry.usageReservePct`가 보는 coding-plan quota와 다르다.
- Anthropic: 구독 OAuth는 자사 앱용이고 제3자 사용의 허용 범위는 공식 문서마다 다르다([법적 고지](https://code.claude.com/docs/en/legal-and-compliance), [Agent SDK 안내](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan), 확인: 2026-11-13). OMP의 `anthropic` OAuth 요청은 Claude Code User-Agent와 시스템 프롬프트를 보내므로(`omp://provider-quirks.md`, OMP 18.20.0 확인: 2026-11-13) 응답 성공·한도 차감을 허용 근거로 쓰지 않는다. 정책상 분명한 경로는 API 키와 [Max·Ultra·Team 월 API 크레딧](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans)(구독 한도와 별개)이며, 저장 OAuth가 환경 변수 API 키보다 우선하므로 API 키 경로는 명시적으로 설정한다(`omp://providers.md`, 확인: 2026-10-15).
- OpenAI: OMP의 `openai-codex` 로그인은 고정 Codex CLI client ID를 재사용해 OpenAI의 [오픈소스 구독 연동](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)(`dynamic_agent_client` 동적 등록) 경로가 아니며 이 경로의 공식 허용·금지는 확인되지 않았다(`omp://provider-quirks.md`, 확인: 2026-10-15). 성공한 실호출을 공식 승인으로 확대하지 않는다.
- Google: [Antigravity 약관](https://antigravity.google/terms) §6과 [Gemini CLI FAQ](https://github.com/google-gemini/gemini-cli/blob/main/docs/resources/faq.md)는 제3자 도구가 Antigravity·Gemini CLI OAuth로 백엔드에 접근하는 것을 위반·계정 정지 사유로 명시한다(조회: 2026-10-10). OMP의 `google-gemini-cli`·`google-antigravity`는 이 제품 OAuth로 내부 백엔드에 직접 추론하므로(`omp://provider-quirks.md`) OMP 추론 자격증명으로 쓰지 않고 `google`(`GEMINI_API_KEY`)·`google-vertex`를 쓴다.
